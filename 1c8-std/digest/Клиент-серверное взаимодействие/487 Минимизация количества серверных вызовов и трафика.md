# Минимизация количества серверных вызовов и трафика (#std487)

**Суть.** Серверные вызовы из клиентского кода — отклонение, привносимое конфигурацией сверх обращений
платформы: на действие пользователя дополнительных вызовов быть не должно.

**Обязательно**
- Разработку вести с контролем количества серверных вызовов из клиентского кода, а в отдельных
  случаях и объёма передаваемых данных (1.1).
- На каждое действие пользователя клиентский код конфигурации не выполняет дополнительных вызовов на
  сервер; любое исключение требует обоснования. Типовое исключение — неявный вызов при первом обращении
  к ещё не скомпилированному клиентскому общему модулю (1.1).
- Для режима с низкой скоростью соединения и мобильного клиента оптимизировать не только число вызовов,
  но и трафик (1.2).
- Код запуска приложения — обработчики `ПередНачаломРаботыСистемы` и `ПриНачалеРаботыСистемы` модуля
  приложения — в простейшем случае не приводит к обращениям на сервер; когда данные всё же нужны,
  передавать на клиент все параметры запуска за один вызов, а параметры, нужные из разных мест
  клиентского кода, получать функцией общего серверного модуля с повторным использованием
  возвращаемых значений (2.1).
- Периодические вызовы объединять в один и делать его по возможности не чаще одного раза в двадцать
  минут (3.1).
- Форму из кода открывать за один вызов методом `ОткрытьФорму` (до платформы 8.2 включительно — также
  `ОткрытьФормуМодально`), параметры передавать параметром `Параметры` (4.1).
- Данные, нужные клиентским обработчикам открытия формы, заранее размещать в реквизитах формы в
  `ПриСозданииНаСервере` (4.2).
- Обработчики завершения фоновых заданий объединять в один, который за один серверный вызов проверяет
  готовность и забирает результат, а интервал периодического обработчика брать по рекомендациям
  статьи 642; с «Библиотекой стандартных подсистем» длительные операции запускать через общие модули
  `ДлительныеОперации` и `ДлительныеОперацииКлиент` (4.3).
- Локальная команда формы приводит не более чем к одному серверному вызову: данные для чисто клиентских
  операций готовят заранее, серверную бизнес-логику выполняют за один вызов (5.1).
- Временное хранилище использовать одним из двух способов: на время жизни формы по её уникальному
  идентификатору с очисткой после использования либо с предварительной инициализацией и
  переиспользованием (8.3).
- Выбор из справочника и глобальная команда — не более одного серверного вызова из кода, того, к
  которому приводит `ОткрытьФорму` (`ОткрытьФормуМодально`) (5.2, 6.1).
- Открытие формы подбора из клиентского кода — не более двух обращений на сервер, закрытие — тоже не
  более двух (8.2).
- Вместо дополнительного вызова в клиентских `ПередЗаписью` и `ПослеЗаписи` размещать серверную логику в
  `ПередЗаписьюНаСервере`, `ПриЗаписиНаСервере`, `ПослеЗаписиНаСервере`, а данные передавать через
  параметр `ПараметрыЗаписи` или реквизиты формы (9).
- Клиентские методы и свойства, приводящие к серверному вызову (`ПолучитьИзВременногоХранилища`,
  `УдалитьИзВременногоХранилища`, свойства `Заголовок`, `Доступность`, `Подсказка`, `ТолькоПросмотр` поля
  формы, `ПолучитьФункциональнуюОпциюИнтерфейса`, `ПолучитьФункциональнуюОпциюФормы`; полный список — в
  синтаксис-помощнике), объединять в один серверный вызов: одно временное хранилище либо перенос логики в
  серверную процедуру, вызываемую с клиента однократно (10).
- С «Библиотекой стандартных подсистем» пользоваться её программным интерфейсом: серверный код запуска —
  в `ПриДобавленииПараметровРаботыКлиентаПриЗапуске` и `ПриДобавленииПараметровРаботыКлиента` модуля
  `ОбщегоНазначенияПереопределяемый`, на клиенте — `ПараметрыРаботыКлиентаПриЗапуске` или
  `ПараметрыРаботыКлиента` модуля `СтандартныеПодсистемыКлиент` (2.2).
- Периодические механизмы «Библиотеки стандартных подсистем»: ожидание длительной операции —
  `ОжидатьЗавершение` модуля `ДлительныеОперацииКлиент`; серверные оповещения —
  `ПриДобавленииСерверныхОповещений` модуля `ОбщегоНазначенияПереопределяемый`,
  `ПриОтправкеСерверногоОповещения` и `ПриПолученииСерверногоОповещения` названного в описании модуля;
  периодическая отправка данных с клиента — `ПередПериодическойОтправкойДанныхКлиентаНаСервер` и
  `ПослеПериодическогоПолученияДанныхКлиентаНаСервере` модуля `ОбщегоНазначенияКлиентПереопределяемый`,
  `ПриПериодическомПолученииДанныхКлиентаНаСервере` модуля `ОбщегоНазначенияПереопределяемый`
  (3.2, 3.2.1, 3.2.3, 3.2.4).

**Не надо**
- Напрямую вызывать серверные процедуры и функции из кода модуля приложения, модуля управляемого
  приложения и модуля внешнего соединения (2.1).
- Обращаться к серверу из клиентских обработчиков `ПриОткрытии` и `ПриПовторномОткрытии` при открытии
  формы — это не допускается (4.2).
- Вызывать при открытии формы серверные функции с повторным использованием возвращаемых значений: их
  результат кешируется только после первого вызова, и первое открытие даст лишнее обращение (4.2, 10).
- Подключать при открытии формы несколько разных обработчиков ожидания
  (`ПодключитьОбработчикОжидания`), проверяющих готовность фоновых заданий (4.3).
- Выполнять дополнительные серверные вызовы из кода при формировании отчёта, в том числе обращаться к
  серверу из `ПриОткрытии` и `ПриПовторномОткрытии` формы отчёта: вместо этого открывать форму с
  параметром `СформироватьПриОткрытии` = `Истина` либо устанавливать его в `ПриСозданииНаСервере` (7.1).
- Передавать потенциально большой массив данных параметром формы подбора: хранимый в параметре типа
  `ДанныеФормыКоллекция`, он может оказаться на клиенте неполным, и данные формы будут дочитаны с
  сервера (8.1).
- Передавать с клиента на сервер больше данных, чем нужно для задачи: если процедуре нужно одно значение
  реквизита, вызов не делают контекстным (11).
- Возвращать значения параметров обратно с сервера на клиент — вместо этого делать функцию (12).
- Периодические серверные вызовы в формах начальной страницы: вместо них кнопка `Обновить`, а если
  вызовы всё же нужны — отключёнными по умолчанию и не чаще одного раза в минуту (3.2.2).

**Совет**
- Отладку клиент-серверного взаимодействия для низкой скорости соединения вести в режиме имитации
  задержек серверных вызовов (1.2).
- Вместо периодических вызовов с клиента для проверки состояния сервера применять механизм уведомлений
  клиентов — `МенеджерУведомленийКлиента` (3.1).
- Для проверки состояния сервера ради отдельно открытой формы допустимы бесконтекстные (быстрые)
  вызовы, но период выбирают как можно больший в рамках задачи (3.2.2).
- После выбора из справочника серверную бизнес-логику допустимо выполнять за один дополнительный
  серверный вызов (6.3).
- Передачу данных между формой объекта и формой подбора вести через временное хранилище, читая и
  записывая его на сервере (8.2).
- Фоновые задания целесообразно объединять в одно, экономя ресурсы сервера на их запуск (4.3).
- Параметры процедур и функций, вызываемых с клиента на сервер, указывать с префиксом `Знач`: это
  экспортные процедуры общих модулей с признаком `Вызов сервера` и процедуры модулей форм и команд с
  `&НаСервере`, `&НаСервереБезКонтекста` или без директивы (12).

См. также: 459 (значения, влияющие на поведение клиента), 724 (модули с повторным использованием), 642 (длительные операции на сервере), 628 (объект ДанныеФормыКоллекция), 636 (контекстная и внеконтекстная передача управления).
