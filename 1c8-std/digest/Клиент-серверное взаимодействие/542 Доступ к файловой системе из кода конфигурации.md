# Доступ к файловой системе из кода конфигурации (#std542)

**Суть.** Временные файлы заводит платформа, двоичные данные — потоками в памяти, файл между клиентом
и сервером — через временное хранилище, путь с клиента непроверенный.

**Обязательно**
- Имя временного файла — `ПолучитьИмяВременногоФайла`, кроме веб-клиента (1.1).
- В веб-клиенте имена — из `КаталогВременныхФайлов` и `УникальныйИдентификатор`, временный каталог с
  «Библиотекой стандартных подсистем» — `ФайловаяСистемаКлиент.СоздатьВременныйКаталог` (1.3).
- Временный файл и каталог удалять самому, на автоудаление не рассчитывать (1.4).
- Работу с временным файлом на сервере завершать в одном вызове; между вызовами — временное хранилище
  (`ПоместитьВоВременноеХранилище`, `ПолучитьИзВременногоХранилища`) (1.5).
- Передавая большие данные файлами между сеансами, обеспечить общее хранилище, доступное со всех серверов
  кластера, учёт файлов в регистре, удаление при завершении процесса и регламентную очистку (1.6).
- Поток после чтения двоичных данных закрывать (2.2).
- Файл, с которым работают клиент и сервер, передавать через временное хранилище (3).
- В БСП файл с клиента — `ФайловаяСистемаКлиент.ЗагрузитьФайл`, `ЗагрузитьФайлы`, с сервера —
  `ФайловаяСистемаКлиент.СохранитьФайл`, `СохранитьФайлы` (3.1, 3.2).
- Между серверными вызовами данные файла держать по `УникальныйИдентификаторФормы` (в БСП —
  `ИдентификаторФормы` в `ПараметрыЗагрузки`), при повторном помещении прежнее удалять вручную (3.1).
- Совместимость имён файлов между операционными системами обеспечивать и без локализации (4).
- В именах из кода — только английские буквы и цифры, текстовые файлы только в UTF-8; исключение —
  формат сторонней системы (4.1).
- Исключить чтение и изменение файлов, не предусмотренных проектным решением (6).
- Файл на сервере перед работой проверять: он во временном или ином предусмотренном каталоге (6.5).
- Работа с временным файлом — в одной процедуре, путь от `ПолучитьИмяВременногоФайла` и неизменный, файл
  удалён (6.6).

**Не надо**
- Хранить путь или имя файла в реквизитах формы (6.1).
- Передавать путь к файлу в параметры серверных процедур форм и экспортных процедур общих модулей (6.2).
- Писать файлы в `КаталогПрограммы` — он только для чтения и запуска (6.7).

**Совет**
- Имя временного каталога тоже брать у `ПолучитьИмяВременногоФайла` (1.2).
- У служебных реквизитов объекта в данных формы при записи на сервере проверять, что значение не
  изменено на клиенте (6.1).
- В БСП — `ФайловаяСистема.УдалитьВременныйФайл()`, `ФайловаяСистема.УдалитьВременныйКаталог`,
  `ФайловаяСистема.ОбщийКаталогВременныхФайлов` (1.4, 1.6).
- Двоичные данные брать потоками в памяти: `ПотокВПамяти`, `ЗаписьДанных`, `ЧтениеДанных` (2, 2.1).
- Файловая система допустима, когда платформа не даёт данные в памяти (2.3).
- Файл с клиента — `ПоместитьФайлНаСерверАсинх`, `ПоместитьФайлыНаСерверАсинх`,
  `НачатьПомещениеФайлаНаСервер`, `НачатьПомещениеФайловНаСервер` (3.1).
- Файл с сервера — `ПолучитьФайлССервераАсинх`, `ПолучитьФайлыССервераАсинх`,
  `НачатьПолучениеФайлаССервера`, `НачатьПолучениеФайловССервера` (3.2).
- Имя от пользователя разрешать русским с транслитерацией
  (`СтроковыеФункцииКлиентСервер.СтрокаЛатиницей`); по умолчанию — англоязычное и UTF-8 (4.2).
- Помнить: доступ идёт под правами пользователя операционной системы — на клиенте запустившего
  приложение, на сервере запустившего сервер «1С:Предприятия» или веб-сервер (5, 5.1, 5.2).
- Расширение с клиента проверять по коллекции допустимых либо методом
  `ОбщегоНазначенияКлиентСервер.ЗаменитьНедопустимыеСимволыВИмениФайла` (6.3).
- Путь из данных базы пропускать через тот же метод (6.4).
- Администраторам — профили безопасности (6.8).

См. также: 700 (внешние компоненты и расширения платформы), 467 (общие требования к конфигурации).
