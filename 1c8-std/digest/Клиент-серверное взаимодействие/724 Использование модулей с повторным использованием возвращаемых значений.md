# Использование модулей с повторным использованием возвращаемых значений (#std724)

**Суть.** Общий модуль с повторным использованием возвращаемых значений (кэш) хранит результат функции на
время сеанса или на время вызова; неоправданный кэш съедает память, а хранит он недолго.

**Обязательно**
- Кэш применять для экономии вычислительных ресурсов сервера и минимизации клиент-серверного
  взаимодействия (1).
- Помещать в кэш только данные, к которым будут часто обращаться: значение удаляется через 20 минут после
  вычисления или через 6 минут после последнего использования, а также при нехватке памяти в рабочем
  процессе, его перезапуске и переключении клиента на другой процесс (2.2).
- Соседнюю экспортную функцию того же модуля вызывать с явным указанием имени модуля: результат
  «внутреннего» вызова не кэшируется (4).

**Не надо**
- Кэшировать данные, которые вычисляются быстрее, чем берутся из кэша, например строковые константы (2.1).
- Кэшировать константы примитивных типов и прочие данные из базы, выгода от кэширования которых
  неочевидна (2.1).
- Широкий диапазон значений входных параметров у функций кэша (2.3).
- Изменять данные, полученные из кэша: возвращается не копия, а ссылка на один и тот же объект в
  памяти (3).
- Возвращать из функций модуля со свойством «На время сеанса» значения типов `МенеджерВременныхТаблиц`,
  `Запрос` и объекты базы данных (например, `ДокументОбъект`, `ОтчетОбъект`) — ни непосредственно, ни в составе
  коллекций, ни во временном хранилище: платформа этого не проверяет (5).
- Применять кэш чрезмерно и неоправданно: излишнее потребление памяти (2).

**Совет**
- Кэшировать имеет смысл данные из базы данных, из внешних источников данных или полученные сложными
  ресурсоёмкими вычислениями (2.1).
- Возвращать из кэша значения, состояние которых изменить нельзя: `ФиксированныйМассив`,
  `ФиксированнаяСтруктура` (3).
