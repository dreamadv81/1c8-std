# Таймауты при работе с внешними ресурсами (#std748)

**Суть.** Без предельного времени ожидания обращение к внешнему ресурсу может длиться бесконечно:
программа «зависает» либо часть её функциональности становится недоступна.

**Обязательно**
- Задавать таймаут при работе с внешними ресурсами объектами `WSОпределения`, `WSПрокси`,
  `HTTPСоединение`, `FTPСоединение`, `ИнтернетПочтовыйПрофиль` (1).
- Для быстрых операций, например проверки доступности сервера, величину таймаута выбирать
  соответственно небольшой (2).
- Когда операция объективно долгая из-за этапов Send или Cache Read — передачи больших объёмов на
  веб-сервер или загрузки большого файла, — ставить большой таймаут по оценке объёма данных, но не более
  12 часов (2).
- Веб-сервисы, операции которых долго отрабатывают из-за этапа Wait и не могут быть ускорены,
  переводить на асинхронный режим: фоновое задание плюс операции проверки готовности и получения
  результата (3.3).
- Операции с таймаутом 60–120 и 120–180 секунд вызывать только после контрольной операции `Ping`
  (табл.).

**Не надо**
- Выбирать таймаут более 3 минут в общем случае: при недоступности удалённой стороны это даёт эффект
  «зависания» программы (2).

**Совет**
- Величину таймаута определять исходя из ожидаемого времени конкретной операции: за него проходят все
  шесть этапов — DNS Lookup, Connect, Send, Wait, Receive, Cache Read (2).
- Рекомендуемые величины: получение описания веб-сервиса — 7 с; проверка корректности адреса,
  взаимодействие с менеджером сервиса и прочие «быстрые» операции — 10–20 с; сведения об одном
  контрагенте, обмен сообщениями, отправка SMS, удалённое администрирование в модели сервиса — 60–120 с;
  передача сообщений обмена через веб-сервис или получение файла до 1 Мб — 120–180 с; загрузка файла
  более 1 Мб — размер в мегабайтах × 128, а при неизвестном размере предельное время загрузки, но не
  более 43200 с (4, табл.).
- При разработке веб-сервиса с таймаутом операций ориентировочно больше 20 секунд предусматривать
  отдельную контрольную операцию `Ping`, сначала получать прокси с таймаутом 7 секунд и вызывать `Ping`,
  и только после этого — основной прокси; с «Библиотекой стандартных подсистем» — функция `WSПрокси`
  модуля `ОбщегоНазначения` с поддержкой `Ping`, для HTTP(S) и FTP(S) — подсистема «Получение файлов
  через Интернет» (3, 3.1).
- Для других видов внешних ресурсов применять аналоги `Ping`: для REST API — контрольную тестовую
  команду (ответ с кодом 200 обычно значит, что сервис работает), для FTP- и WebDAV-ресурсов —
  контрольную отправку файла-пустышки (3.2).
