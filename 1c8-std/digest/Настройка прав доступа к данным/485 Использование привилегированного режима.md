# Использование привилегированного режима (#std485)

**Суть.** Привилегированный режим даёт операции с недоступными данными и ускоряет работу, снимая
проверку прав; неоправданный — угроза безопасности данных.

**Обязательно**
- Режим применять, когда проверку прав требуется отключить по логике либо допустимо отключить
  ради скорости, не нарушая прав пользователя (1.2).
- Подчинённые регистры (движения документов), нужные пользователю для отчётов, оставлять только
  на чтение, а писать в привилегированном режиме — права на запись проверяются лишь у
  регистратора (2.1).
- Регистры, не нужные пользователю ни в отчётах, ни в командном интерфейсе: прав на чтение не
  давать, читать и писать в привилегированном режиме (2.2).
- Заранее недоступные данные для разрешённой операции получать в привилегированном режиме, но с
  гарантией, что они не уйдут на клиент и на сервере послужат только запланированной
  операции (2.3).
- Привилегированный режим ради производительности — когда он не даёт не разрешённых
  пользователю действий и данных; переход при получении данных для отчёта рассчитывать
  тщательно (2.4).
- Обращение к экспортной процедуре или функции в сеансе с недостаточными правами вызывает
  исключение стандартного вида; отдельных проверок обычно не требуется — с ролями и RLS
  исключение возникает само (запрос без `РАЗРЕШЕННЫЕ`, `ПолучитьОбъект` от недоступной ссылки,
  вызов недоступного метода глобального контекста и в других аналогичных случаях); вручную —
  `ВыполнитьПроверкуПравДоступа` (3.2).
- Включать точечно: установить прямо перед действием, выполнить его без проверки прав, отключить
  сразу после, продолжить в непривилегированном режиме (3.3).
- Переход в привилегированный режим — средствами платформы: свойства документа
  «Привилегированный режим при проведении» и «Привилегированный режим при отмене проведения» для
  `ОбработкаПроведения` и `ОбработкаУдаленияПроведения` (а при выборке, ограниченной для
  пользователя, свойства снять и звать
  `УстановитьПривилегированныйРежим`); свойство бизнес-процесса «Привилегированный режим»;
  «Привилегированный режим при получении» у функциональных опций;
  `УстановитьПривилегированныйРежим` в любом месте модуля; общий модуль со свойством
  «Привилегированный» (4).

**Не надо**
- Безусловно включать привилегированный режим в начале экспортной процедуры или функции,
  работающей на сервере: это отключает проверку прав текущего пользователя, особенно в клиентском
  прикладном программном интерфейсе сервера. Исключение — действие или возвращаемое значение,
  разрешённое абсолютно всем категориям пользователей (3.1).

**Совет**
- Запрос с параметрами отбора, уже прошедшими проверку RLS, допустимо выполнить в
  привилегированном режиме (2.4).

**Пример**
```bsl
Процедура ИзменитьИлиУдалитьДанные(...) Экспорт
  ВыполнитьПроверкуПравДоступа(...); // если у пользователя недостаточно прав, будет исключение
  УстановитьПривилегированныйРежим(Истина); // отключаем проверку прав доступа
  // изменяем данные в привилегированном режиме
КонецПроцедуры
```
