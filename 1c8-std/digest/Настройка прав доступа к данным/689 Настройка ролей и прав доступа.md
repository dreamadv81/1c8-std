# Настройка ролей и прав доступа (#std689)

**Суть.** Роли атомарны — по элементарным функциям; неограниченный доступ без RLS даёт
`ПолныеПрава` с `АдминистраторСистемы`. Обязателен для УП (ERP), УТ 11 и их библиотек, остальным
рекомендуется.

**Обязательно**
- Роли — «атомарные», на элементарные функции: типовому внедрению новые роли не нужны; из них
  собирают профили и назначают средствами «Библиотеки стандартных подсистем» (БСП). Исключение —
  внешним пользователям даётся исчерпывающий набор прав к нужным объектам (1.1).
- Удаление ссылочных объектов — только у `ПолныеПрава` и `АдминистраторСистемы`; у нового объекта
  интерактивное удаление в `ПолныеПрава` отключить; флаг «Устанавливать права для новых
  объектов» — только у `ПолныеПрава`, у остальных ролей снят (1.3, 1.4, 1.5).
- Все проводимые документы несут «Привилегированный режим при проведении» и «Привилегированный
  режим при отмене проведения», поэтому роли на изменение подчинённых регистратору регистров
  обычно не нужны; исключение — документы для корректировки записей регистров: проводятся с
  проверкой прав, и роли нужны (1.7, 3.2).
- Во всех функциональных опциях выставлен «Привилегированный режим при получении»; исключение —
  параметризованные ФО с намеренно разными значениями по правам (1.8).
- Чтение неконфиденциальных данных и общедоступных функций (у ссылочных — просмотр и ввод по
  строке) — в `БазовыеПрава<ИмяБиблиотеки>` и `БазовыеПраваВнешнихПользователей<ИмяБиблиотеки>`,
  без отдельной роли; вторая — при внешних пользователях (1.10).
- Объекты объединить в элементарные функции: внутри функции доступ не различается ни в одной
  задаче; каждый объект — в одной (2.1, 2.3).
- Функции со ссылочными объектами и независимыми регистрами сведений — роли `Чтение<ИмяФункции>`
  и `ДобавлениеИзменение<ИмяФункции>` либо `Изменение<ИмяФункции>` при автоматическом или
  административном добавлении (3.1).
- Права ролей (если есть у объекта): `Чтение` — Чтение, Просмотр, Ввод по строке; `Изменение` —
  плюс Изменение, Редактирование, у документов Проведение, Отмена проведения, Интерактивное
  проведение, Интерактивная отмена проведения, Интерактивное изменение проведенных, у регистров
  Управление итогами; `ДобавлениеИзменение` — плюс Добавление, Интерактивное добавление,
  Интерактивная пометка удаления, Интерактивное снятие пометки удаления (3.1).
- Документы журнала в одной функции — чтение и просмотр журнала её ролям (4.1).
- Константу меняет только администратор системы — изменение и редактирование у `ПолныеПрава`
  либо `АдминистраторСистемы`, они же дают чтение и просмотр (5.1).
- Константу меняет пользователь — чтение, просмотр, изменение, редактирование в «настроечную»
  роль либо в новую `Изменение<ИмяКонстанты>` (5.2).
- Чтение и просмотр константы — ролям `БазовыеПрава<ИмяБиблиотеки>` и
  `БазовыеПраваВнешнихПользователей<ИмяБиблиотеки>`; конфиденциальная — роль
  `Чтение<ИмяКонстанты>`, доступная только администратору её не требует (5.3, 5.4).
- Подсистеме верхнего уровня — роль `Подсистема<ИмяПодсистемы>` с правом просмотра; она же —
  просмотр формы настроек и справочников подсистемы (6.1, 6.2).
- Отчёту с отдельной настройкой прав и отчёту по нескольким функциям — роль
  `ПросмотрОтчета<ИмяОтчета>` с использованием и просмотром (7.2, 7.3).
- Обработке-рабочему месту (своя команда в ГКИ) — роль
  `ИспользованиеОбработки<ИмяОбработки>` с просмотром и использованием, общей форме —
  `ИспользованиеОбщейФормы<ИмяОбщейФормы>`; исключения — п. 6.2 (8.1, 8.4, 8.5).
- Прочим обработкам и командам печати из обработок — роль `БазовыеПрава<ИмяБиблиотеки>` (8.2, 9.1).
- Обработкам только для администратора программы — роль `ПолныеПрава` (или `АдминистраторСистемы`
  при работе в сеансе без установленного разделителя), без отдельных ролей (8.3).
- Просмотр команды без изменения данных — ролям на просмотр объекта: и на чтение, и на изменение;
  с изменением данных — роли на изменение объектов (9.1, 9.2).
- Дополнительное право — роль `<НаименованиеПрава>` без доступа к объектам и без слова «Право» в
  наименовании; наличие роли проверять в коде, `ПолныеПрава` проходит проверку без неё в
  профиле (10.1, 10.2).
- В БСП проверять функцией `Пользователи.РолиДоступны` (10.2).
- Роли только для внешних пользователей называть с определённым префиксом, например
  `Самообслуживание` (11).
- Устаревшие объекты с префиксом `Удалить` исключить из всех ролей, кроме `ПолныеПрава` и
  `АдминистраторСистемы` (12).

**Не надо**
- Давать интерактивное удаление ссылочных объектов любой роли, включая `ПолныеПрава` и
  `АдминистраторСистемы` (1.3).
- Заводить роли с общими правами (`Администрирование`, `ТонкийКлиент`) кроме стандартных ролей
  БСП; в новой роли их выключать (1.9).
- Давать одной ролью права на объекты разных подсистем (1.11).
- Относить объекты разных библиотек к одной элементарной функции (2.4).
- Создавать отдельную роль на журнал документов: он входит в элементарную функцию либо доступен
  полноправному пользователю (4.2).
- Объединять права к разным обработкам-рабочим местам в одной роли (8.1).
- Реализовывать дополнительные права иначе, чем проверкой наличия роли или права (10.3).

**Совет**
- Право только администратора системы достаточно дать `ПолныеПрава` либо
  `АдминистраторСистемы` (1.6).
- Сомневаясь, разделить объекты по разным функциям (2.2).
- Отчёт по данным одной функции можно оставить в её ролях (7.1).
- Однотипные отчёты можно объединить в функцию, если они не входят в другие и прав к ним не
  настраивают отдельно (7.4).
