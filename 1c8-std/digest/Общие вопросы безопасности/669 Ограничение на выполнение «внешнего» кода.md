# Ограничение на выполнение «внешнего» кода (#std669)

**Суть.** Внешний код приходит внешними отчётами и обработками, расширениями, внешними компонентами;
в нём возможны деструктивные действия, особенно в модели сервиса.

**Обязательно**
- С «Библиотекой стандартных подсистем» внешний код подключать только её средствами: расширения —
  «Базовая функциональность», внешние отчёты и обработки — «Дополнительные отчёты и обработки»,
  компоненты — «Внешние компоненты» (1).
- Интерактивное открытие внешних отчётов и обработок через меню Файл — Открыть по умолчанию отключать
  всем категориям пользователей, предусмотрев в настройках разрешение; разрешая, предупредить
  администратора и пользователей: обращать особое внимание на источник и не открывать файлы от
  тех, с кем нет договорённости о разработке (2).
- Предупреждать администраторов об опасности перед подключением любого внешнего кода (3).
- В предупреждении сообщать, что код из недостоверных источников вредит компьютерам, серверам и
  данным; администратор может отказаться от загрузки и повторить её после аудита (3.1).
- Обновление конфигурации из `.cf` и `.cfu`, восстановление из копии и загрузку dt-файла в режиме
  «1С:Предприятия» давать только роли «Администратор системы» и только интерактивно текущим
  пользователем, а не служебным с полными правами; перед обновлением и восстановлением показывать
  предупреждение о надёжности источника файла; при обновлении через Интернет — защищённое соединение и
  надёжный источник, о чём предупредить при настройке подключения (4).
- При загрузке произвольных файлов предусмотреть для администратора список разрешённых (запрещённых)
  расширений и блокирование открытия исполняемых файлов из программы (5).
- На клиенте всегда задавать вопрос, устанавливать ли внешнюю компоненту (6, 6.1).
- Сторонние компоненты хранить в справочнике с записью только у администратора и подключать по
  навигационной ссылке на реквизит с двоичными данными (6.2).
- Компоненты в составе конфигурации хранить в макетах типа «Внешняя компонента» (6.3).
- Код извне загружать только из надёжных источников, по защищённым каналам, с проверкой подлинности
  сервера; то же для данных по HTTPS и FTPS у `HTTPСоединение`,
  `FTPСоединение`, `WSПрокси`, `WSОпределения`, `WSСсылкаМенеджер.СоздатьWSПрокси` (7).
- Права сеанса регламентного задания ограничить, программно создав и указав для запуска служебного
  пользователя с урезанными правами: по умолчанию задания идут под полными правами, безопасный режим
  их не уменьшает (8).
- С БСП обновление и восстановление вести только подсистемами «Обновление конфигурации» и «Резервное
  копирование ИБ», работу с файлами — только подсистемой «Работа с файлами» (4, 5).
- В БСП компоненты подключать методами библиотеки, полностью исключив платформенные
  `ПодключитьВнешнююКомпоненту`, `НачатьУстановкуВнешнейКомпоненты`, `УстановитьВнешнююКомпоненту`,
  `НачатьПодключениеВнешнейКомпоненты`, `ЗагрузитьВнешнююКомпоненту`: из макета —
  `ОбщегоНазначенияКлиент.ПодключитьКомпонентуИзМакета`,
  `ОбщегоНазначения.ПодключитьКомпонентуИзМакета`, из хранилища —
  `ВнешниеКомпонентыКлиент.ПодключитьКомпоненту` (6.4).
- В БСП защищённое соединение — `НовоеЗащищенноеСоединение` модуля `ОбщегоНазначенияКлиентСервер` (7).

**Не надо**
- Выполнять на сервере в небезопасном режиме любой код, не входящий в прикладное решение: это
  запрещено; ограничение не распространяется на прошедший аудит и на код клиента (1).
- Выдавать остальным пользователям предупреждения при исполнении внешнего кода, подключение которого
  администратор уже подтвердил (3.2).
- Отключать предупреждения об опасных действиях вне подсистем библиотеки (3.2).
- Загружать внешние компоненты не из конфигурации от источников, к которым нет доверия (6.1).
- Давать пользователям без административных прав загружать, устанавливать и подключать внешние
  компоненты на сервере (6.1).
- Подключать сторонние компоненты по имени файла или идентификатору программы (6.2).
- Давать пользователям вводить алгоритмы и запросы для `Выполнить` и `Вычислить`, менять схемы
  компоновки с внешними функциями и загружать схемы из файлов (1).

**Совет**
- Права сеанса задания ограничивают одним из трёх: рекомендуется пустой список ролей — чтение
  и изменение в привилегированном режиме, вычисление кода в безопасном; можно реальный пользователь;
  можно специальные роли на чтение таблиц алгоритма. В БСП первый способ —
  `РегламентныеЗаданияСервер.УстановитьСлужебногоПользователяРегламентногоЗадания` в начале
  обработчика (8).
