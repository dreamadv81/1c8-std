# Безопасное хранение паролей (#std740)

**Суть.** Пароль к внешнему ресурсу в информационной базе не хранят, а если без хранения нельзя —
держат отдельно и закрыто.

**Обязательно**
- Логин и пароль запрашивать у пользователя и передавать сразу, не сохраняя в базе (2).
- Пароли извлекать только на сервере и непосредственно перед использованием (3.3).
- Привилегированный режим включать перед вызовом функций работы с паролями, а не внутри них:
  безопасность обеспечивает вызывающий код (3.3).
- Для хранения в базе заводить отдельный объект метаданных, например регистр сведений, с безопасным
  доступом на уровне прав «1С:Предприятия» (3.1).
- С «Библиотекой стандартных подсистем» пользоваться безопасным хранилищем паролей —
  `ЗаписатьДанныеВБезопасноеХранилище`, `ПрочитатьДанныеИзБезопасногоХранилища`,
  `УдалитьДанныеИзБезопасногоХранилища` модуля `ОбщегоНазначения`: чтение и запись только в
  привилегированном режиме, данные закрыты, хранилище исключено из планов обмена (3.2).

**Не надо**
- Хранить пароли и конфиденциальную информацию в базе: слабее всего файловые, чей файл любой
  пользователь копирует целиком (2).
- Хранить пароли в реквизитах объектов, с которыми ведётся повседневная работа (3.1).
- Хранить пароли в реквизитах формы: при маскированном вводе пароль уходит на клиент открытым (3.3).

**Совет**
- Хранение в базе допустимо, когда запрос на каждую операцию неудобен и сохранения на клиенте мало
  либо работа с ресурсом идёт на сервере независимо от пользователей; их предупреждают о
  последствиях (3).
