# Ограничения на использование Выполнить и Вычислить на сервере (#std770)

**Суть.** Опасен не только код, введённый в режиме «Предприятие», но и код, собранный на сервере из
параметров с клиента.

**Обязательно**
- `Выполнить` и `Вычислить` с кодом из параметров серверных процедур считать опасными; на код
  клиента ограничение не распространяется, особенно опасны такие методы в модулях с
  `ВызовСервера` (1).
- Вызов `Выполнить` или `Вычислить` на сервере предварять `УстановитьБезопасныйРежим(Истина)` (2).
- В режиме сервиса по каждому разделителю конфигурации вызывать
  `УстановитьБезопасныйРежимРазделенияДанных` (2).
- Код, не выполняемый в безопасном режиме, пускать через аудит и класть в справочник с записью только
  у ответственного за безопасность (3).
- В модели сервиса при переносе данных из локальной версии обеспечить отключение всех пользовательских
  фрагментов кода и текстов запросов (4).
- С «Библиотекой стандартных подсистем» вместо `Выполнить` и `Вычислить` —
  `ОбщегоНазначения.ВыполнитьВБезопасномРежиме()`, `ВычислитьВБезопасномРежиме()`, вместо сборки строки
  вызова — `ВыполнитьМетодКонфигурации()`, `ВыполнитьМетодОбъекта()`; справочник проверенного кода —
  подсистема «Дополнительные отчёты и обработки» (2, 3).

**Совет**
- Сценарий: внешний код во внешнюю обработку или отчёт (в крайнем случае — фрагментом текста),
  администратору с пометкой про небезопасный режим, аудит, затем в справочник; вместо них — экспортный
  метод проверенной обработки либо специальная процедура для фрагмента (3).

См. также: 669 (выполнение внешнего кода), 678 (безопасность интерфейса сервера).
