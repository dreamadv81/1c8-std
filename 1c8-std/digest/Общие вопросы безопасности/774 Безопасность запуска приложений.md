# Безопасность запуска приложений (#std774)

**Суть.** Строку запуска собирают из проверенных частей, а запускают через интерфейс библиотеки.

**Обязательно**
- Строку запуска собирать только из проверенных частей (1).
- Часть строки из базы, поля ввода или хранилища настроек перед запуском проверять: безопасны данные
  без знаков "$", "\`", "|", "||", ";", "&", "&&". Это все способы запуска: `КомандаСистемы`,
  `ЗапуститьПриложение`, `НачатьЗапускПриложения`, `ПерейтиПоНавигационнойСсылке`, COM-объекты
  "Wscript.Shell" и "Shell.Application" (1).
- С «Библиотекой стандартных подсистем» — её интерфейс: проводник с фокусом на файле —
  `ФайловаяСистемаКлиент.ОткрытьПроводник`; файл в ассоциированной программе — `ОткрытьФайл`, она
  исключает исполняемые; веб-страница, протоколы `mailto:`, `skype:`, `tel:`, навигационная ссылка —
  `ОткрытьНавигационнуюСсылку` (2, 2.1, 2.2, 2.3).
- Исполняемые файлы, системные команды, команды на сервере, код возврата и потоки вывода и ошибок —
  через `ФайловаяСистемаКлиент.ЗапуститьПрограмму` и `ФайловаяСистема.ЗапуститьПрограмму` (2.4).
- Команду с наивысшими правами (в Windows — запрос UAC) делать на управляемой форме кнопкой или
  пунктом меню, а на кнопке показывать значок щита — картинку `ЗначокЩита` библиотеки; щит стоит слева
  от надписи и на кнопке, и на пункте меню (3, рис.).

**Не надо**
- Формировать ссылку по протоколу `file://` для открытия проводника или файла: для этого есть
  `ОткрытьПроводник` и `ОткрытьФайл` (2.3).
- Формировать исполняемые файлы программно, например bat-файл во временном каталоге: политика
  безопасности может запрещать неразрешённое, а каталог в исключениях сам становится угрозой (2.5).

**Совет**
- Вместо этого собирать строку запуска для `ФайловаяСистема.ЗапуститьПрограмму` либо передавать
  параметры во временный исполняемый файл со статическим содержимым — командной строкой или
  неисполняемым файлом параметров (2.5).
