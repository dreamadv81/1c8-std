# Разработка конфигураций с повторным использованием общего кода и объектов метаданных (#std551)

**Суть.** Методическая рекомендация: общую функциональность нескольких конфигураций выносят в
конфигурации-библиотеки, они стоят на поддержке друг у друга; код делится на три области
видимости.

**Совет**
- Общий код и объекты нескольких конфигураций выносить в библиотеки: разработка централизована,
  версия выходит продуктом, повторное использование — через постановку на поддержку (1).
- Как правило, библиотеку разрабатывают только ради прикладных решений — конечных потребителей
  иерархии; библиотека-наследник стоит на поддержке у библиотеки-родителя (2).
- Выделять три области видимости: программный интерфейс — для сторонних потребителей, служебный
  программный интерфейс — только для других функциональных подсистем этой же библиотеки,
  служебные процедуры и функции — только для других объектов этой же подсистемы (3).
- Программный интерфейс для конкретных потребителей держать в месте, определённом документацией,
  вызывать только определённым потребителем и размещать в подразделе «Для вызова из других
  подсистем» (3).
