# Разработка ролей в библиотеках (#std668)

**Суть.** Библиотека даёт готовые роли к своим данным, её RLS работает в решениях «как есть».

**Обязательно**
- В большинстве случаев библиотека обязана дать готовый набор ролей к своим данным —
  справочникам, регистрам (2).
- Исключения: объект подчинён владельцу; объект ждёт существенного переопределения; библиотека
  содержит алгоритмы, а не данные (2).
- Поставляемый RLS разрабатывать так, чтобы в решениях он использовался «как есть», без
  доработки (3).
- Нет настройки прав на уровне записей — тексты RLS удалить из библиотечных ролей при
  внедрении; есть свои сущности, в разрезе которых настраивается доступ и к библиотечным
  объектам, — тогда же добавить в RLS логику для них либо не поставлять роли к таким
  объектам (3).
- При использовании правил поставки всем библиотечным ролям задавать «Изменения разрешены»:
  добавление и удаление метаданных неявно меняет роли (4).

**Не надо**
- Разрабатывать в библиотеке объекты, специфичные для конкретного потребителя: их создают при
  внедрении (1).

**Совет**
- В библиотеку включать объекты, которые в неизменном или переопределённом виде войдут в
  потребителей (1).

См. также: 488 (стандартные роли), 553 (переопределяемые объекты), 689 (настройка ролей и прав доступа).
