# Обработчики обновления информационной базы (#std690)

**Суть.** Действует для конфигураций на базе «Библиотеки стандартных подсистем» и уточняет
требования других стандартов: каждая библиотека сообщает о себе сведения для обновления ИБ, а
обработчики обновления дообрабатывают данные после реструктуризации базы.

**Обязательно**
- Каждая библиотека сообщает имя, версию, список обработчиков обновления и зависимости от других
  библиотек; сведения размещаются в общем модуле библиотеки, имя которого начинается с
  `ОбновлениеИнформационнойБазы…` (1.1).
- Такой же модуль определить для основной конфигурации, а имена модулей всех используемых
  библиотек явно перечислить в процедуре `ПриДобавленииПодсистем` общего модуля
  `ПодсистемыКонфигурацииПереопределяемый` (1.1).
- Общий модуль `ОбновлениеИнформационнойБазы…` создавать по шаблону из статьи:
  `ПриДобавленииПодсистемы` (`Имя`, `Версия`, `ТребуемыеПодсистемы`,
  `РежимВыполненияОтложенныхОбработчиков`), `ПриДобавленииОбработчиковОбновления`,
  `ПередОбновлениемИнформационнойБазы`, `ПослеОбновленияИнформационнойБазы`,
  `ПриПодготовкеМакетаОписанияОбновлений`, `ПриОпределенииРежимаОбновленияДанных`,
  `ПриДобавленииОбработчиковПереходаСДругойПрограммы`, `ПриЗавершенииПереходаСДругойПрограммы` (1.1).
- Обработчики обновления библиотек, от которых зависит данная, обязаны вызываться раньше её
  собственных; при циклических зависимостях или их отсутствии порядок вызова задаётся порядком
  добавления модулей в `ПриДобавленииПодсистем` (1.1).
- Автогенерируемые строки, которые программно записываются в ИБ (например, наименования
  предопределённых элементов справочников, ПВХ), писать по стандарту об автогенерированных
  данных (1.2).
- Описание нового обработчика добавлять в `ПриДобавленииОбработчиковОбновления` по шаблону:
  `Версия`, `Процедура` (полное имя экспортной процедуры), `НачальноеЗаполнение`,
  `РежимВыполнения` (1.3).
- Номер версии задавать в формате «Р.П.В.С»; версия «\*» значит, что обработчик выполняется при
  каждом обновлении ИБ независимо от версии конфигурации (обновление служебных, системных данных);
  если свойство `Версия` не задано, свойство `НачальноеЗаполнение` должно быть установлено в
  `Истина` (1.3).
- `РежимВыполнения` — «Монопольно», «Оперативно» или «Отложенно»; не задан — обработчик
  монопольный. Монопольный требует отсутствия активных сеансов пользователей, регламентных
  заданий, внешних соединений и подключений по веб-сервисам, иначе обновление версии программы
  прерывается; если монопольный хотя бы один обработчик конфигурации, все оперативные выполняются
  в монопольном режиме (1.3).
- У обязательного обработчика (`Версия` = «\*») режим «Монопольно» ставить только тогда, когда он
  сам программно определяет, нужен ли монопольный режим: его вызывают дважды с параметром
  `Параметры` типа `Структура`, и при первом вызове, в режиме проверки (`МонопольныйРежим` =
  `Ложь`), код не должен модифицировать данные ИБ, а понадобились изменения — обязан установить
  свойство в `Истина` и прекратить выполнение; при втором вызове (`МонопольныйРежим` = `Истина`)
  данные менять можно, а изменение свойства игнорируется (1.3).
- Оперативные обработчики применять в редких случаях — когда важно сократить ожидание
  пользователей при переходе на исправительные релизы без изменений структуры данных, обновление
  на которые выполняется динамически (1.3).
- При параллельном режиме отложенного обновления (`РежимВыполненияОтложенныхОбработчиков` =
  «Параллельно») отложенные обработчики писать по стандарту параллельного режима отложенного
  обновления (1.3).
- Процедуру-обработчик оформлять экспортной и располагать в модуле менеджера того объекта
  метаданных, обновление которого она выполняет (2.1).
- Когда обработчик невозможно соотнести с конкретным объектом метаданных, допустимо расположить
  его в серверном общем модуле, по смыслу связанном с выполняемой обработкой, — в служебной части
  модуля, в подразделе «Обновление ИБ» (2.2).
- Алгоритм обработчика строить так, чтобы не прерывать и не зацикливать обработку данных, не
  оставлять необработанные данные и не требовать от пользователя дополнительных действий для
  продолжения; любое невыполнение обработчика рассматривать как логическую ошибку и
  перепроектировать его логику (3.1).
- Обработчик рассчитывать на неоднократное выполнение: на одних и тех же данных результат обязан
  быть идентичен при любом количестве вызовов (3.1).
- В пределах одной версии (свойство `Версия`) работоспособность обработчика не должна ставиться в
  зависимость от очерёдности выполнения; проявились такие зависимости — обработчики объединить в
  один (3.1).
- Если в конфигурации предусмотрены планы обмена РИБ с отборами, учитывать, что в обновляемом
  подчинённом узле данные бывают неполными (есть движения по регистру, а регистратор отсутствует);
  обновление таких данных обработчик обязан пропускать (3.1).
- Обработчик не должен содержать лишних, избыточных действий с данными — должен выполняться
  максимально быстро (3.2).
- Отключать бизнес-логику при обработке данных, в большинстве случаев установкой признака
  `ОбменДанными.Загрузка` (3.2.1).
- Для большинства обрабатываемых данных отключать регистрацию изменений на узлах планов обмена: в
  распределённой информационной базе обработка должна выполняться независимо в каждом узле, а при
  обмене между произвольными конфигурациями — не приводить к выгрузке данных в базы-получатели;
  исключение — создание ссылочных объектов, которые должны быть перенесены в другие узлы РИБ с тем
  же значением реквизита `Ссылка` (3.2.2).
- Вместо простой записи объекта ставить `ОбменДанными.Загрузка`, `ДополнительныеСвойства` с
  `ОтключитьМеханизмРегистрацииОбъектов` и `ОбменДанными.Получатели.АвтоЗаполнение` = `Ложь`; с
  БСП 2.1.4 и выше — процедуру `ЗаписатьДанные` общего модуля `ОбновлениеИнформационнойБазы` (3.2.3).
- Перед процедурой-обработчиком ставить комментарий: первая строка — версия конфигурации, для
  которой предназначен обработчик, последующие отвечают, какие данные меняются и какие изменения
  вносятся (3.3).
- Ставя конфигурацию на поддержку новой версии библиотеки, увеличивать номер версии конфигурации:
  без этого обработчики обновления информационной базы не запустятся (4.1).

**Не надо**
- Логика интерактивного взаимодействия с пользователем в обработчике (3.1).
- Вызывать исключение в параллельных отложенных обработчиках — оно остановит всю процедуру
  обновления; в остальных видах обработчиков исключение допустимо только при критической ошибке,
  когда исчерпаны все другие возможности обхода проблемы: остановка обновления сделает запуск
  невозможным, пока причины ошибки не будут устранены (3.1).

**Совет**
- Большие объёмы данных обновлять отложенно, чтобы сократить время простоя: монопольные
  обработчики предназначены для данных, обработка которых обязана завершиться к моменту входа
  пользователей в программу (1.3).
- Для частичного отключения бизнес-логики предусматривать дополнительный признак в
  `ДополнительныеСвойства` (3.2.1).

**Пример**
```bsl
Обработчик = Обработчики.Добавить();
Обработчик.Версия = "<номер версии>";
Обработчик.Процедура = "<полное имя экспортной процедуры>";
Обработчик.НачальноеЗаполнение = {Истина|Ложь};
Обработчик.РежимВыполнения = {"Монопольно"|"Оперативно"|"Отложенно"};
```
