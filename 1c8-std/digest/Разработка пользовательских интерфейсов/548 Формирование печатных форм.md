# Формирование печатных форм (#std548)

**Суть.** Требования к командам вывода на печать: права, один запрос, соответствие экранной
форме, поля.

**Обязательно**
- Для формирования печатной формы пользователю достаточно прав на чтение данных, по которым она
  формируется, и на выполнение инициирующей команды (1).
- При множественной печати выборку данных выполнять в одном запросе, результаты обходить в
  цикле (2).
- Правила 3.1–3.5 — для нерегламентированных печатных форм (3).
- Печатная и экранная формы соответствуют по составу и порядку строк табличных частей (3.1).
- Строки, уже сгруппированные в экранной форме, печатать с такой же группировкой (3.2).
- В табличных частях печатных форм всегда выводить колонку «Номер строки» (3.3).
- Когда «Номер строки» на экранной форме не отображается, нумеровать строки в порядке
  вывода (3.4).
- Порядок строк одинаков на различных СУБД: выводить их отсортированными по номеру строки или
  другому полю (4).
- Данные выводить в печатные формы полностью, без обрезания (5.1).

**Не надо**
- Дополнительно группировать строки табличных частей при печати (3.1).
- Устанавливать на сервере размер полей табличного документа заведомо меньше физических
  ограничений принтера; нулевые поля недопустимы (6).

**Совет**
- Предусматривать в функции печати множественную печать нескольких объектов (2).
- Заголовок колонки с номером строки зависит от прикладной специфики: регламентированное «Номер
  по порядку» либо «№» (3.5).
- Индексировать поля, по которым выполняется сортировка (4).
- В табличных макетах ставить строкам табличных частей `АвтоВысотаСтроки` объекта
  `ОбластьЯчеекТабличногоДокумента` в `Истина`: длинные тексты не обрежутся (5.2).
- Размер полей табличного документа не менять, кроме явно регламентированных или
  стандартизированных случаев (6).

См. также: 436 (однотипные запросы), 412 (упорядочивание результатов), 645 (названия печатных форм), 789 (изменение макета пользователем).
