# Ограничения при использовании динамических списков (#std489)

**Суть.** Условия для разработчика, управляющего группировками динамического списка: свои
группировки пользователь ставит настройкой списка, и оптимальной производительности разработчик
не гарантирует.

**Обязательно**
- В списках с большим количеством записей группировка — только по проиндексированным полям: для
  построения группировки список выбирает все уникальные значения поля (1.4).
- Многоуровневые группировки допускаются только при двух условиях: поле первой группировки
  проиндексировано и обладает хорошей селективностью — последующие список отрабатывает уже без
  индексов, по всем отобранным первой (1.5).
- У иерархических списков `НачальноеОтображениеДерева` — `НеРаскрывать` либо
  `РаскрыватьВерхнийУровень` (2).
- Отключая строку поиска, ставить `ПоложениеСтрокиПоиска` и `ПоложениеУправленияПоиском` в `Нет`
  (у форм, созданных в предыдущих версиях платформы, `Нет` уже установлено по умолчанию) (3).

**Не надо**
- `РаскрыватьВсеУровни` у `НачальноеОтображениеДерева` иерархического списка: скорость открытия
  больших списков снижается критично (2).
- Группировки по полям-характеристикам объекта метаданных: вывод характеристик делает ЛЕВОЕ
  СОЕДИНЕНИЕ с таблицей характеристик, и отбор по одной характеристике неэффективен даже при
  индексе (1.6).

**Совет**
- Группировки — в списках с заведомо небольшим числом записей (не более нескольких сотен): его
  обеспечивает отбор в запросе списка либо неотменяемый пользователем отбор формы (1.3).
- Строку поиска в командной панели допустимо отключать, когда основные сценарии поиска ею не
  выполняются: поиск почти всегда работает только с начала слов (3).
