# Запросы в динамических списках (#std732)

**Суть.** Данные списка сразу видит пользователь: к скорости запроса требования выше, чем в отчётах
и обработках.

**Не надо**
- Конструкции, «утяжеляющие» запрос (настоятельно): `РАЗЛИЧНЫЕ` и `СГРУППИРОВАТЬ ПО`, `ВЫБОР` в
  предложении `ГДЕ` или в условиях соединения, упорядочивание по полученному `ВЫБОР` полю, в том
  числе пользовательское (4).
- Соединения с большим количеством реальных таблиц (ориентир — не более 4), с вложенными запросами,
  с виртуальными таблицами (5.1).
- Индексировать все поля подряд «на всякий случай»: избыточные индексы неоправданно нагружают
  запись (3).

**Совет**
- Делать запросы списков простыми, а для этого оптимизировать архитектуру хранения данных (1).
- Выбрать один из трёх режимов: динамическое считывание включено (рекомендуется) — выбирается
  примерно столько записей, сколько видимых строк; выключено при не виртуальной основной таблице
  либо `СрезПервых`, `СрезПоследних`, `ЗадачиПоИсполнителю`, `КритерииОтбора`, `ДвижениеСубконто` —
  по 1000 записей в буфер, менее эффективно; выключено без основной таблицы — запрос «как есть»,
  буфер от 1000 записей, только для заведомо маленьких выборок (2).
- Рассмотреть индексирование полей: по которым выполняется соединение, на которые наложены условия
  запроса, выведенных быстрыми отборами, по которым упорядочивают или группируют и по которым
  ожидается частое упорядочивание (группировка) пользователем; фактический запрос к СУБД зависит
  ещё и от предопределённых настроек отборов, порядка и группировки СКД (3).
- Соединяться только с небольшим количеством реальных таблиц; оптимально — одна основная (5.1).
- Соединение с виртуальными таблицами допустимо в отдельных случаях: `СрезПоследних`
  (`СрезПервых`) регистра сведений с заведомо небольшим количеством записей; будут использованы
  хранимые итоги регистра; запрос к `Остатки` платформа превратит в чтение хранимых итогов без
  группировок (5.2).
- Временные таблицы — только с заведомо небольшим количеством записей: в списке они не кешируются,
  а формируются при каждом считывании (5.3, 5.3.1).
- Когда запрос не переделать виртуальными таблицами с ограничениями либо без них, соединяться
  вместо них с временными (5.3.2).
- Последний запрос списка выбирает данные только из временной таблицы — это уже не динамический
  список: перепроектировать запрос и, скорее всего, метаданные (5.3.3).
- Обращение к полям «через точку» неявно соединяет дополнительные таблицы — считать и их (5.4).
- Скорость проверять именно под неполными правами с ограничениями доступа (RLS): условия
  присоединяются к таблицам автоматически и замедляют список (5.5).
- Составное поле в соединениях, отборах, упорядочивании и прочем держать только ссылочных типов, а
  известный заранее тип выражать `ВЫРАЗИТЬ` (6).
- Запрос списка менять «на лету» на более оптимальный, когда это возможно (7).
- Когда перечисленное не помогает, отказаться от части возможностей списка: от вывода незначимой
  информации, усложняющей запрос, и от сервисной группировки (8, 8.1).
- Выводить данные в таблицу или дерево значений вместо списка — появится привилегированный режим;
  годится при заведомо малых данных (десятки-сотни записей), обязательных отборах или своей
  порционности (8.2).
- Вспомогательные колонки, по которым не отбирают, не сортируют и не группируют, брать
  обработчиком `ПриПолученииДанныхНаСервере` — одним запросом сразу для всех строк (9).
- Ограничивать отбор, сортировку и группировку по ним методами
  `УстановитьОграниченияИспользованияВГруппировке`, `УстановитьОграниченияИспользованияВПорядке`,
  `УстановитьОграниченияИспользованияВОтборе` (9).
