# Блокирующее чтение остатков в начале транзакции (#std661)

**Суть.** Блокировка от чтения остатков держится до конца транзакции: регистр с контролем, записанный
первым, заставляет ждать остальных.

**Обязательно**
- Итоги в ряде случаев читать блокирующе: при контроле остатков на проведении; остатки ушли в
  минус — транзакцию отменять, такой документ проводить нельзя (1.1).
- Чтение остатков делать блокирующим: двое не должны одновременно читать один остаток за период,
  счёт и значение измерения, иначе спишут больше него (1.2).
- Разобрать, какие остатки нуждаются в блокирующем чтении: на приходном документе контроль не нужен,
  при перепроведении со списанием не больше прежнего — тоже (2).
- В начале транзакции, например в `ОбработкаПроведения`, явно записать движения регистров без
  контроля остатков, всегда в одном порядке — например, алфавитном (2).
- У них разделитель итогов включён, а `БлокироватьДляИзменения` наборов записей — `Ложь` (2).
- Прочие действия транзакции выполнять между двумя записями движений (2).
- В самом конце транзакции явно записать движения регистров с контролем остатков, задав их наборам
  `БлокироватьДляИзменения` = `Истина` против взаимоблокировки (2).
- Для каждого выполнить запрос контроля: он читает только отрицательные остатки по заданному набору
  значений измерений; нашлись — транзакцию отменять, пусто — фиксировать (2).

**Совет**
- Явная управляемая блокировка (`ДЛЯ ИЗМЕНЕНИЯ` в автоматическом режиме) в этом запросе не нужна:
  остатки уже заблокированы своей записью (2).
- Перенести блокирующее чтение ближе к концу транзакции: из `ПередЗаписью` модуля набора записей в
  `ПриПроведении` модуля документа, после записи всех движений (текст).

См. также: 648 (ответственное чтение), 663 (разделение итогов у регистров бухгалтерии).
