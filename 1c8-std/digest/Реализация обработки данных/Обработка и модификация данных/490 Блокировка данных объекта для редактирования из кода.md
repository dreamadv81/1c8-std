# Блокировка данных объекта для редактирования из кода (#std490)

**Суть.** Пессимистическая блокировка данных для редактирования нужна конкурентной работе
пользователей с объектами базы: записывать заблокированные данные она другим сеансам не запрещает,
а лишь не даёт двум объектам захватить одни и те же данные. В форме платформа ставит её сама на
объект основного реквизита (1.3).

**Обязательно**
- Прежде чем изменять существующий объект информационной базы из кода, заблокировать его: так видно,
  не заблокирован ли он уже, и так его правку стараются предотвратить в других сеансах и у других
  экземпляров объекта в этом же сеансе (1.1).
- Блокировать методом объекта `Заблокировать` либо методом глобального контекста
  `ЗаблокироватьДанныеДляРедактирования` (1.2).

**Не надо**
- Проверять блокировку объектов для редактирования у операций, которые по логике работы приоритетнее
  интерактивных действий пользователя, например у загрузки данных при обмене (2).
- Проверять её у действий, гарантированно идущих в монопольном режиме, например в процедурах
  обновления и первоначального заполнения данных информационной базы (2).

**Совет**
- Если по задаче заблокированный объект надо пропустить — `Заблокировать` в `Попытка`,
  предупреждение в журнал регистрации, повтор при следующем вызове (1.2).
