# Транзакции: правила использования (#std783)

**Суть.** Транзакция — только для неделимого по бизнес-логике изменения; исключение внутри
запрещает её фиксацию, вложенных транзакций у платформы нет — отсюда ошибка «В этой транзакции
уже происходили ошибки».

**Обязательно**
- `НачатьТранзакцию` и `ЗафиксироватьТранзакцию`/`ОтменитьТранзакцию` — парные и в одном методе (1.1, 1.2).
- `НачатьТранзакцию` стоит сразу перед `Попытка`; всё после неё — внутри одной `Попытка`, включая чтение и
  блокировку; `ЗафиксироватьТранзакцию` — последней в `Попытка`; в `Исключение` первым — `ОтменитьТранзакцию` (1.3).
- Пока после исключения транзакция ещё активна (например, исключение во вложенной), к базе не
  обращаться — в том числе неявно, например за представлением ссылки (1.4.4).
- В одной транзакции — только неделимые по бизнес-логике действия: проведение записывает документ и все его
  движения, отдельные объекты в одну транзакцию не объединяются (2.1, 2.1.1).
- Ресурсоёмкие расчёты и проверки заполнения — до транзакции; контроль остатков — простым запросом после
  записи (2.3).
- Длинных транзакций избегать: порция записи не дольше ~20 с под нагрузкой, загрузка режется на порции (2.2).
- Запись в регистр с отключением итогов выполнять в транзакции вместе с отключением и включением
  итогов: иначе в других сеансах возможна ошибка при получении среза последних (3.1).

**Не надо**
- Явная транзакция ради одной записи объекта — платформа откроет её сама; явно — только при ответственном
  чтении (1.4.1).
- Явная транзакция в методе, который зовут только из `ПередЗаписью`/`ОбработкаПроведения` (1.4.2).
- Вызывать в транзакции внешние ресурсы — сетевые папки, интранет- и интернет-сайты, почтовые,
  FTP-, HTTP-, веб-сервисы: обращение бывает долгим, ресурс — недоступным, возможен тайм-аут (2.3).

**Совет**
- В `Исключение` — запись в журнал регистрации; при вложенной транзакции в конце `Исключение` —
  `ВызватьИсключение`, иначе внешняя не откатится и платформа сама поднимет ошибку (1.3).
- Вложенные транзакции усложняют код: открывать их оправдано, только когда на своём уровне нужно
  уточнить текст ошибки для пользователя (1.4, 1.4.3).
- Ожидание блокировки 20 с и исключение — повод вынести действия за транзакцию, упростить алгоритм и
  проверить блокировки (2.2.2).
- Несколько несвязанных объектов в одной транзакции — допустимое ради оптимизации исключение из
  пункта 2.1.1; порцию обработки выбирают взвешенно: золотая середина между длительностью
  транзакции и объёмом фиксируемых данных с одной стороны и числом транзакций с другой (2.1.2).

**Пример**
```bsl
НачатьТранзакцию();
Попытка
    … // блокировка, чтение, запись
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ЗаписьЖурналаРегистрации(…, УровеньЖурналаРегистрации.Ошибка, , , ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение; // есть внешняя транзакция
КонецПопытки;
```
