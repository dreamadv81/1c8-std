# Многократная запись регистров сведений и накопления (#std792)

**Суть.** Регистр пишут одним набором и порциями, а изменения применяют режимами замещения: запись
по одной записи в цикле и перезапись целого набора ради нескольких изменённых строк идут в разы
дольше и раздувают журнал транзакций СУБД.

**Обязательно**
- Порционная запись наборов — ориентир в большинстве случаев 1000 записей (1).
- Вместо перезаписи большого набора записывать только изменения (1).
- Для оптимальной записи регистров применять режимы замещения в сочетании с вычислением изменённых
  записей (1).
- У регистров, подчинённых регистратору, поле `НомерСтроки` (вместе с `Регистратор` — ключ строки;
  режим `Слияние` для них исключён, а в режиме `Удаление` платформа сама обновляет номера
  оставшихся записей) считать исключительно счётчиком строк в пределах регистратора: порядок строк
  не должен иметь значения для прикладного использования (4.4).
- При вычислении изменений исключать `НомерСтроки` из сравнения (4.4).
- Порядок записи у регистра с регистратором: сначала набор со сброшенным отбором в режиме
  `Обновление` — из добавляемых и обновляемых записей числом не более удаляемых, с номерами строк
  удаляемых; остались записи для удаления — набор в режиме `Удаление` из их ключей строк; иначе
  оставшиеся добавляемые и обновляемые — набор в режиме `Добавление` (`Ложь`), без
  `РасширенныеРежимыЗамещения` и без заполнения `НомерСтроки` (с версии 8.3.26) (4.4).

**Не надо**
- Записывать наборы записей регистров сведений и накопления в цикле по одной или нескольким записям:
  это в несколько раз медленнее записи регистра одним набором (1).
- Перезаписывать большой набор, в котором меняется не более 30 % записей: перезапись удаляет все
  записи по отбору набора и вставляет все новые, включая неизменившиеся (1).

**Совет**
- Добавляя записи в пустой регистр, задавать параметру `РежимЗамещения` метода `Записать` значение
  `Ложь` (добавление) (1).
- В остальных случаях брать режимы замещения `Слияние`, `Удаление` (с версии 8.3.26) и `Обновление`
  (с версии 8.3.27): они обрабатывают записи пакетно, порциями (1).
- Изменения считать запросом, не загружая новые записи в сервер из СУБД: сравнить их с записями
  регистра и взять только различия — лишние записи на удаление, недостающие и новые версии
  изменённых на слияние (текст).
- Запись движений оптимизировать, кроме особых случаев, когда регистр обновляют сразу по нескольким
  регистраторам: закрытие месяца, восстановление последовательности взаиморасчётов (4.4).
