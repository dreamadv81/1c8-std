# Разыменование ссылочных полей составного типа в языке запросов (#std654)

**Суть.** Обращение к полям «через точку» даёт неявное соединение с таблицей, на которую ссылается
поле, а при ограничениях доступа на уровне записей (RLS) — и с таблицами RLS; у поля составного
типа таких таблиц столько, сколько в нём возможных типов.

**Обязательно**
- Каждое исключение из правила о разыменовании составных полей тщательно анализировать (1.2).
- Указывать ровно столько возможных типов поля составного ссылочного типа, сколько
  необходимо (2.1).
- Тщательнее анализировать прикладную логику и назначать полю ровно те типы ссылок, которые нужны
  для решения задачи (2.1).
- Жертвовать компактностью хранения данных ради производительности: помещать соответствующие данные
  в исходную таблицу запроса — например, завести в регистре реквизит `ДатаРегистратора` и заполнять
  его при проведении. Дублирование немного увеличит объём, но существенно повысит
  производительность и стабильность запроса (2.2).
- При необходимости жертвовать компактностью и универсальностью кода ради производительности:
  ограничивать количество возможных типов функцией `ВЫРАЗИТЬ`, поскольку для конкретного запроса
  все типы ссылки, как правило, не нужны (2.3).

**Не надо**
- Получать данные «через точку» от ссылочных полей составного типа — крайне нежелательно:
  соединение пойдёт со всеми таблицами, ссылки на которые могут оказаться в поле, и с их RLS (1.2).
- Избыточность при создании полей составных ссылочных типов (2.1).
- Без необходимости использовать типы «любая ссылка», «ссылка на любой документ» и подобные (2.1).

**Совет**
- Универсальный запрос, работающий в разных ситуациях с разными типами ссылки, формировать
  динамически, подставляя в `ВЫРАЗИТЬ` нужный при данных условиях тип (2.3).

См. также: 477 (самодостаточность регистров), 728 (реквизиты составного типа).
