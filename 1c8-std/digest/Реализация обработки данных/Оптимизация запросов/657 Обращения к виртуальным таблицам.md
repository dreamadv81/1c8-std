# Обращения к виртуальным таблицам (#std657)

**Суть.** Условия виртуальной таблицы задают в её параметрах, иначе оптимизатор СУБД легко
ошибётся с планом.

**Обязательно**
- Передавать в параметры виртуальной таблицы все относящиеся к ней условия (1).
- Передавать в условия наиболее простые конструкции — `Измерение = Значение` (2.1).
- Из нескольких условий с подзапросами выбрать одно, годное по условиям выше и отфильтровывающее
  больше всего записей, остальные наложить на внешний запрос (2.3).

**Не надо**
- Обращаться к виртуальным таблицам условиями в секции `ГДЕ` (1).
- Подзапросы и соединения в параметрах виртуальной таблицы — запрос работает медленно; соединения
  тут и явные, и неявные «через точку», и из RLS (2.1).

**Совет**
- Ограничивать количество выбираемых записей на самом раннем этапе запроса (1).
- Подзапрос в параметрах — с одной таблицей, без соединений (2.2).
- Подзапрос по таблице табличной части — без обращения к реквизитам шапки; по таблице с
  табличными частями — без обращений к ним (2.2).
- Подзапрос по временной таблице — без условий `ГДЕ`; по постоянной `ГДЕ` допустим, если условие
  выполняется для 80 % случаев и более (2.2).
- Подзапрос по постоянной таблице — когда в RLS нет подзапросов и соединений, а только простые
  условия; иначе переписать запрос с временной таблицей или в привилегированном режиме (2.2).
- Применять временные таблицы вместо переноса условий на внешний запрос: одно условие по кортежу
  измерений вместо трёх `В (…)` (2.3).
