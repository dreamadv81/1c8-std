# Эффективные условия запросов (#std658)

**Суть.** Основное условие ограничивает выборку больше других, объединено по `И` и ищется по
индексу; дополнительное присоединено к нему по `И` и любой сложности (`НЕ`, `<>`, арифметика,
функции).

**Обязательно**
- Условия писать оптимально, чтобы длительность не росла с объёмом данных (1).
- Поля основного условия в `ГДЕ`, `ПО` и виртуальных таблицах должны быть проиндексированы (1).
- Основное условие уточнять дополнительным только через `И` (1).
- Учитывать: разные поля объекта дают разные индексы, а не один общий, и основное условие берёт
  лишь один (1).
- Для первого и всех полей индекса, кроме последнего, — только `=` и `И` (1).
- Для последнего или единственного поля индекса допустимы `=`, `>`, `<`, `>=`, `<=`, `ПОДОБНО`,
  `МЕЖДУ`, `В`, `ИЛИ` (приводимое к `В`) (1).
- Для условий в `ГДЕ` и в виртуальной таблице индексировать поля основной таблицы выборки (1).
- Для условий в `ПО` ЛЕВОГО соединения индексировать поля правой таблицы (1).
- Для условий в `ПО` ВНУТРЕННЕГО соединения индексировать поля бо́льшей таблицы (1).
- В основном условии `ИЛИ` — только для последнего или единственного поля индекса и только когда
  заменяется на `В`; переписывать специально не нужно (2.1).
- `ВЫБОР` использовать только в дополнительных условиях (5).
- Арифметические операции над полями выполнять только в дополнительных условиях (6).
- Пересмотреть состав ролей так, чтобы доступ к объекту давала одна роль (7).
- Если ролей к объекту несколько, задавать для одного права одинаковые условия RLS: добавится
  одно условие, без `ИЛИ` (7).

**Не надо**
- Арифметические операции, функции, отрицания и неравенства в основном условии (1).
- Литерал `ПОДОБНО`, начинающийся с `_` или `%` (3).
- Назначать одному пользователю больше одной роли с разным RLS для одного права объекта: оба
  условия добавятся через `ИЛИ` — запрос медленный и с блокировками (7).

**Совет**
- Строить основное условие по индексам, которые платформа создаёт сама (1).
- Требования можно не соблюдать, когда данных всегда мало (менее 1000 записей) или запросы очень
  редки (1.1).
- Когда записей много, а требования невыполнимы: преобразовать условия, добавить вычисляемые при
  записи индексированные поля, иначе пересмотреть архитектуру (1.2).
- `ИЛИ` по разным полям переписывать через `ОБЪЕДИНИТЬ ВСЕ` с индексом на каждом; замена годится
  не всегда — проверить результат (2.1).
- В дополнительном условии `ИЛИ` можно использовать без ограничений (2.2).
- Функции работы со строками приводить к `ПОДОБНО`, а с датой — к `МЕЖДУ` (3, 4).
- Когда фрагмент строки не в начале, завести вычисляемое при записи поле и искать `ПОДОБНО` по
  нему (3).
