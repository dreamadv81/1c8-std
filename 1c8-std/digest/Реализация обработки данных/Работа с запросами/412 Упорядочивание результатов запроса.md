# Упорядочивание результатов запроса (#std412)

**Суть.** Без `УПОРЯДОЧИТЬ ПО` порядок записей не определён: он меняется при смене СУБД, её версии
и параметров.

**Обязательно**
- Использовать `УПОРЯДОЧИТЬ ПО`, когда алгоритм обработки зависит от порядка записей или результат
  представляется пользователю (1.1).
- При сортировке по полю, потенциально содержащему `NULL`, учитывать: в разных СУБД порядок
  сортировки различается — заворачивать поле в `ЕСТЬNULL` (1.2).
- Результаты, отображаемые пользователю, упорядочивать по полям примитивных типов (1.3).
- Упорядочивание по ссылочным полям заменять упорядочиванием по их строковым представлениям:
  иначе порядок строк выглядит для пользователя случайным (1.3).
- При `РАЗЛИЧНЫЕ` упорядочивать только по полям, включённым в выборку (2).
- Причины `АВТОУПОРЯДОЧИВАНИЕ` указывать комментарием непосредственно перед текстом запроса (3).

**Не надо**
- Упорядочивать запросы, по которым формируются движения, если это не часть алгоритма формирования
  движений (списание партий по FIFO): избыточная нагрузка на СУБД (1.1).
- Добавлять `УПОРЯДОЧИТЬ ПО`, когда алгоритму порядок не важен, результат не показывается
  пользователю или заведомо состоит из одной записи (1.4).
- `ПЕРВЫЕ` совместно с `АВТОУПОРЯДОЧИВАНИЕ` — запрещено (3).
- `АВТОУПОРЯДОЧИВАНИЕ` и в остальных случаях: оправдано, только когда порядок не важен, но должен
  быть одинаковым на любой СУБД (3).

См. также: 781 (сортировка в таблице значений).
