# Оформление текстов запросов (#std437)

**Суть.** Текст запроса пишут так, чтобы его читал другой разработчик и открывал конструктор
запросов: заглавные ключевые слова, явные псевдонимы, структура, комментарии.

**Обязательно**
- Все ключевые слова языка запросов писать заглавными буквами (1).
- Ключевое слово `КАК` перед псевдонимом поля источника указывать обязательно (2).
- Текст запроса должен быть структурирован и нагляден (3).
- Нужно стараться, чтобы каждая часть программно собираемого запроса открывалась конструктором
  запросов: так проверяется синтаксис и упрощается сопровождение (6.2).
- Собирая текст программно, имена полей и таблиц подставлять `СтрЗаменить` через
  место-заполнитель, `ПОМЕСТИТЬ` держать в тексте, а не в комментарии, а разделитель пакета
  приписывать отдельной конкатенацией, а не внутрь литерала запроса (6.2).

**Не надо**
- Писать запрос в одну строку, даже короткий (3).

**Совет**
- Указывать и необязательные конструкции запроса, прежде всего явно назначать псевдонимы полям:
  тогда переименование реквизита меняет текст запроса, а не читающий выборку код (2).
- Особенно внимательно относиться к автоматически присваиваемым псевдонимам полей — реквизитов
  других полей: `Касса.Валюта.Наименование` получит псевдоним `ВалютаНаименование`, а не
  `Наименование` (2).
- Вставлять комментарии в сложные для понимания запросы — с вложенными запросами, объединениями,
  соединениями; конструктор запросов удаляет все комментарии автоматически и без
  предупреждения (4).
- При создании объекта `Запрос` комментировать, для чего он используется (5).
- При программной сборке текста запроса комментировать все этапы сборки (6.1).

См. также: 762 (локализация запросов).
