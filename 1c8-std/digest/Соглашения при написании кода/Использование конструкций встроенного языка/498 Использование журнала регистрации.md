# Использование журнала регистрации (#std498)

**Суть.** Журнал регистрации хранит события работы пользователей с базой; администратор разбирает их
по типу, уровню важности и комментарию.

**Обязательно**
- Одна запись журнала — одно событие; записи содержат обязательные атрибуты для анализа (2).
- Метаданные помещать в параметр `Метаданные`, данные — в параметр `Данные` метода
  `ЗаписьЖурналаРегистрации`, а тип события делать более общим (2.1).
- Текст типа события локализуем, при этом всегда задаётся основной язык конфигурации (2.1).
- Уровень важности: ошибки бизнес-логики и сбои — «Ошибка», потенциальные проблемы и не фатальные
  ошибки — «Предупреждение», успешное завершение операции — «Информация»; возможен и более низкий
  «Примечание» (2.2).
- Записывать столько событий, сколько их реально произошло (2.3).
- Текст комментария локализуем (2.3).
- Информацию об исключении писать через
  `ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())` (2.3).
- Падение скорости учитывать и в отчётах по журналу регистрации (3).

**Не надо**
- Включать в тип события избыточную информацию — конкретные значения из базы или внешних
  систем (2.1).
- Помещать в комментарий информацию сразу о нескольких событиях (2.3).
- Помещать в комментарий текстовые данные неизвестного заранее размера — содержимое файлов, ответов
  веб-сервисов: ориентир максимум 10 Кб (2.3).
- Выборка из журнала там, где критична высокая скорость: при больших объёмах она падает
  пропорционально (3).

**Совет**
- Писать в журнал из встроенного языка, когда администратору нужна дополнительная диагностическая
  информация о событиях, которые платформа не записывает, — в интерактивной работе и в фоновых
  (регламентных) заданиях (2).
- Типы событий группировать по функциональному признаку: «Название группы событий.Название
  события» (2.1).
- Для протоколирования событий заводить отдельный регистр либо обращаться к специализированным
  объектам платформы, например `МенеджерФоновыхЗаданий` (3).
