# Использование переменных в программных модулях (#std639)

**Суть.** Переменные модуля — источник трудновоспроизводимых ошибок: область видимости плохо
контролируется; у каждой задачи есть своё средство платформы.

**Обязательно**
- В большинстве случаев вместо переменных модулей использовать подходящие средства платформы (1).
- Предопределённые элементы и перечисления получать на клиенте методом
  `ПредопределенноеЗначение` (3.1).
- Промежуточные результаты по цепочке вызовов в одном вызове передавать параметрами
  процедур и функций (3.2).
- Результаты, сохраняемые между вызовами с клиента, держать в реквизитах формы: серверные
  переменные модуля между вызовами не сохраняются (3.2).
- Переменные управляемого и обычного приложения — для «клиентских параметров сеанса» (4).

**Не надо**
- Кешировать статическую и легко вычисляемую информацию — предопределённые элементы и перечисления —
  в клиентских переменных модуля формы (3.1).

**Совет**
- Параметры из внешнего кода в обработчики подписок и событий модуля объекта передавать через
  `ДополнительныеСвойства` (2.1).
- Внутренние параметры между обработчиками событий модуля объекта передавать неэкспортными
  переменными модуля, недоступными извне (2.1).
- Коды возврата (ошибок) в модуле обрабатывать строковыми константами (2.2).
- Долго вычисляемые и часто используемые значения кешировать модулями с повторным использованием
  возвращаемых значений на время вызова сервера (2.3, 3.1).
- Исключение: если по безопасности результат нельзя вернуть экспортной функцией, его кладут в
  локальную переменную модуля (2.3).
- Исключение: клиентские переменные формы для промежуточных результатов в обработчиках ожидания,
  внешних событий и событий элементов формы (3.2).

См. также: 455 (структура модуля), 459 (повторное использование значений), 443 (предопределённые значения), 640 (параметры процедур), 413 (параметры сеанса).
