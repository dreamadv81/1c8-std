# Вызов исключений в коде (#std790)

**Суть.** Своё исключение вызывают редко, и тогда указывают подходящую категорию ошибки: от неё
зависят заголовок сообщения и типовая рекомендация платформы.

**Обязательно**
- Проверку прав доступа в большинстве случаев выполнять методом `ВыполнитьПроверкуПравДоступа`;
  программно исключение вызывают в редких случаях — при проверке наличия роли (текст).
- Когда анализ типов исключений важен для бизнес-логики, выбрать один из трёх вариантов: строковые
  коды возврата вместо исключений; анализ подходящей категории ошибки в исключении, вызванном
  методом платформы; `ВызватьИсключение` со строковым кодом ошибки в третьем параметре `Код` (текст).
- В событиях `ОбработкаПроверкиЗаполнения`, `ОбработкаПроведения`, `ПередЗаписью`, `ПриЗаписи`,
  `ПередУдалением` устанавливать параметр `Отказ` в значение `Истина` и выводить сообщения
  пользователю: он увидит все блокирующие причины сразу, а не по очереди (3).
- Вызывать исключение, если пользователь не может отработать останавливающее предупреждение в рамках
  операции либо ситуация исключительная и делает бессмысленными остальные проверки (3).

**Не надо**
- Вызывать исключение в общем случае не требуется: платформа сама выводит сообщение с подходящей
  рекомендацией, пишет в журнал подробности со стеком вызовов и шлёт их в сервис регистрации
  ошибок (1, рис.).
- Числовые коды ошибок — код нечитаем; строковые литералы кодов не локализуются (текст).
- Исключения в этих событиях ради останавливающих предупреждений, которые должен отработать
  пользователь (3).

**Совет**
- Исключениям бизнес-логики, которые выводятся пользователю, категорию ошибки указывать не
  требуется: она соответствует `ИсключениеВызванноеИзВстроенногоЯзыка` (текст).
- Остальным исключениям указывать подходящую категорию ошибки — `ОшибкаРаботыСПринтером`,
  `ОшибкаСети`, `НарушениеПравДоступа`: без категории пользователь видит только текст, с ней
  платформа добавляет типовые рекомендации (текст, рис.).
- Вывод исключений проверять без отладки и без режима технического специалиста (текст).
- Программные ошибки (некорректный входной параметр, некорректно встроенная подсистема)
  диагностировать исключением с категорией `ОшибкаКонфигурации`: они для разработчиков, пользователь
  видит «возникла непредвиденная ошибка» с предложением сформировать отчёт (текст, рис.).
- Вариант с кодом ошибки подходит, когда вернуть код затруднительно: ошибка в `ПередЗаписью`,
  `ПриЗаписи` либо пробросить код на верх большого стека сложно (текст).
- Для уникальности включать в коды ошибок префикс подсистемы (2.3.3).
- В конфигурации с Библиотекой стандартных подсистем коды разбирать функцией
  `ОбщегоНазначенияКлиентСервер.ЭтоИсключениеСКодомОшибки`: она находит их рекурсивно во вложенных
  исключениях (текст).
