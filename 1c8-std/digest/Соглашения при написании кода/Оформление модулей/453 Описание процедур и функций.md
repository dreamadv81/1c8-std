# Описание процедур и функций (#std453)

**Суть.** Описание — комментарий перед объявлением процедуры из секций «Описание», «Параметры»,
«Возвращаемое значение», «Пример»; платформа выводит его в контекстной подсказке, EDT берёт
оттуда типизацию.

**Обязательно**
- Процедуры и функции, входящие в программный интерфейс модулей, комментируются обязательно; в
  остальных случаях комментарий может отсутствовать либо быть произвольным текстом (2).
- Комментарий размещается перед объявлением процедуры (функции) (5).
- Секция «Описание» (`Description`) — назначение, достаточное для понимания сценариев
  использования без просмотра исходного кода; может быть единственной секцией у процедуры без
  параметров; не совпадает с именем процедуры; начинается с глагола — у функции, как правило,
  «Возвращает…», а когда результат не основной, с основного действия: «Проверяет…»,
  «Сравнивает…» (5.1).
- Секция «Параметры» (`Parameters`) предваряется строкой «Параметры:», дальше с новой строки
  описания всех параметров; параметров нет — секция пропускается (5.2).
- Описание параметра: с новой строки имя параметра, дефис, список типов, дефис, текстовое
  описание (5.2.1).
- Описание типа обязательно; типы — только существующие в платформе и специальные типы EDT
  (`ОпределяемыйТип.<Имя>`, `СправочникСсылка`, `ОбъектМетаданныхОтчет` и т. п.); имя типа
  простое или составное из двух слов через точку, список типов — через запятую (5.2.1).
- Имя параметра выбирают так, чтобы назначение было понятно в контексте функции без
  пояснений (5.2.1).
- У параметра типа `Структура` и `ТаблицаЗначений` (`ДеревоЗначений`) в описании типа необходимо
  указать ссылку на функцию, выходное значение которой — эта структура или таблица, например на
  функцию-конструктор; метод, работающий с коллекциями универсально, обходится именем типа (5.2.2).
- У параметра или возвращаемого значения типа `Массив` тип элементов указывается ключевым словом
  «из» (`of`); не указывать его допускается только в методах, работающих с массивами
  универсальным образом (5.2.3, 5.3).
- Секция «Возвращаемое значение» (`Returns`) — тип и содержание значения функции, у процедуры её
  нет; предваряется строкой «Возвращаемое значение:», дальше тип, дефис и текст; у составного
  типа каждый тип с новой строки и с дефиса (5.3).
- Секция «Пример» (`Example`) предваряется строкой «Пример:», дальше с новой строки пример
  использования; имя процедуры (функции) пишется вместе с именем общего модуля; из примера
  понятно, что передаётся на входе и что возвращается (5.4).
- В переопределяемых модулях в секции «Пример» — пример реализации переопределяемой процедуры, а
  не пример её вызова (5.4.1).
- Текст всех объявляемых секций имеет отступ относительно заголовка секции начиная с первой
  строки; в многострочном описании одного контекста дополнительный отступ нужен только второй
  строке, следующие выравниваются по ней (5.6).
- Устаревшая процедура (функция): слово «Устарела» (`Deprecated`) в первой строке описания (5.8).
- У процедуры (функции) с директивой компиляции комментарий размещают первым, директиву — за
  ним (6).
- Код процедур и функций отделяется в тексте модуля пустыми строками (7).

**Не надо**
- Комментарии, не дающие дополнительных пояснений о работе не-экспортной процедуры (функции) (4).
- Начинать описание с избыточных слов «Процедура…», «Функция…» и с имени самой процедуры
  (функции): от их удаления смысл не меняется (5.1).

**Совет**
- Описание процедур и функций выполнять в виде комментария к ним; комментировать ли отдельные
  участки кода — решает разработчик по сложности и нестандартности участка (1).
- Прочие процедуры и функции, в том числе обработчики событий, комментировать, если надо пояснить
  назначение или особенности работы; описывать причины невыполнения действий, кажущихся
  неочевидными. Несложной процедуре, чьё назначение следует из имени и имён формальных
  параметров, комментарий допускается не писать (3).
- Текстовое описание параметра заполнять, когда одного имени в контексте функции недостаточно,
  нужна дополнительная информация о типе или наглядный пример ожидаемого значения (5.2.1).
- У параметра типа `СтрокаТаблицыЗначений` (`СтрокаДереваЗначений`) можно задать состав свойств
  по колонкам таблицы-владельца (дерева-владельца) (5.2.4).
- Параметру можно задать одно или несколько дополнительных описаний типов: каждое с новой строки,
  обязательный дефис, список типов, дефис, текстовое описание (5.2.5).
- Описание можно задать ссылкой на функцию-конструктор в формате «см. ПутьКФункции»
  (`see MethodPath`), в том числе на типы реквизитов объекта или формы; нет подходящей
  функции-конструктора — допустима ссылка на параметр другой процедуры (5.2.6).
- Процедуре-событию, которая повторяет состав и порядок параметров процедуры программного
  интерфейса, ставят одну ссылку на неё вместо описания (5.2.6).
- Текстовое описание возвращаемого значения заполнять, когда описания функции недостаточно либо
  нужна информация о типе — например о составе свойств или колонок (5.3).
- Несколько параметров с дополнительными типами — добавить секцию «Варианты вызова»
  (`Call options`): строка «Варианты вызова:», дальше каждый вариант с новой строки — имя функции
  со списком типов в круглых скобках, дефис, описание (5.5).
- В любом месте комментария можно добавить переход к другим объектам конфигурации, процедурам и
  функциям; EDT оформит его гиперссылкой (5.7).

**Пример**
```bsl
// Определяет доступность ролей текущему пользователю.
//
// Параметры:
//   ИменаРолей - Строка - имена ролей через запятую.
//   Параметры  - см. ОбщегоНазначения.ПараметрыПроверки
//              - Структура - дополнительное описание типа.
//
// Возвращаемое значение:
//   - Булево - Истина, если роль доступна.
//   - Неопределено - если роли нет в метаданных.
//
// Пример:
//   Пользователи.РолиДоступны("ОтправкаПоПочте") = Истина.
//
Функция РолиДоступны(ИменаРолей, Параметры) Экспорт
```
