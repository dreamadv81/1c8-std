# Параметры процедур и функций (#std640)

**Суть.** Имена, порядок и число параметров и форма вызова: параметров немного, обязательные
впереди, вызов без громоздких вложений и без пропусков.

**Обязательно**
- Имена формальных параметров — по общим правилам образования имён переменных, от терминов
  предметной области, чтобы назначение параметра было понятно из имени (1).
- Параметры идут в логической последовательности (3).
- Необязательные параметры (со значениями по умолчанию) располагаются после обязательных (4).
- Допустимое значение `Неопределено` передают в функцию явно либо делают этот параметр
  необязательным со значением по умолчанию `Неопределено` (7).

**Не надо**
- Заменять параметры функции другими средствами конфигурирования — переменными модулей,
  реквизитами формы и т. п. (2).
- Громоздкие конструкции при вызове функций: снижают читаемость, повышают вероятность ошибок,
  затрудняют отладку (6).
- Пробелы при вызове методов, процедур и функций: перед открывающей скобкой, после неё, перед
  закрывающей и перед запятыми, когда параметры в одной строке и не опущены (6.3).
- Пропускать обязательные параметры при вызове: в параметр уйдёт `Неопределено`, на которое
  функция может быть не рассчитана (7).
- Больше семи параметров, а со значениями по умолчанию больше трёх: читаемость вызывающего кода
  сильно снижается (5).
- Вложенные вызовы других функций при передаче параметров — разбивать их на отдельные операторы
  вспомогательными локальными переменными; компактный (без переноса выражений) и легко читаемый
  вложенный вызов допустим (6.1).
- Вложенный конструктор `Новый Структура(…)` при вызове; он допустим, только когда свойств
  немного — не более трёх (6.2).

**Совет**
- Располагать параметры по принципу от общего к частному (3).
- Параметров много — группировать однотипные в составные параметры типа `Структура` либо
  пересмотреть логику функции, разделив её на несколько более простых (5).
