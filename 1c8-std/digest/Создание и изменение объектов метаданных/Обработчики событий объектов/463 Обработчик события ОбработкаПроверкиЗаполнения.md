# Обработчик события ОбработкаПроверкиЗаполнения (#std463)

**Суть.** Обработчик проверяет заполнение реквизитов вне транзакции записи: операция прерывается до
записи — самое эффективное место, но не для проверок целостности.

**Обязательно**
- В `ОбработкаПроверкиЗаполнения` проверять правильность заполнения значений реквизитов объекта —
  измерений, ресурсов, реквизитов табличных частей (1.1).
- Пользоваться обработчиком, когда обычной проверки на заполненность уже недостаточно (значение
  связано с другим реквизитом) или требование заполненности не безусловно (1.2).
- Условную проверку — зависящую от других реквизитов или параметризированной функциональной опции —
  оформлять удалением имени реквизита из массива `ПроверяемыеРеквизиты`: собрать массив
  `НепроверяемыеРеквизиты` и вызвать `УдалитьНепроверяемыеРеквизитыИзМассива` (1.2).
- Учитывать, что обработчик вызывается не при каждой записи: при программно инициированной записи он не
  вызывается (1.3).
- Учитывать, что новое состояние объекта ещё не записано: данные для запроса сохранять во временные
  таблицы (2.1).
- Проверки реквизитов, некорректные значения которых ведут к рассогласованности данных,
  выполнять в обработчиках транзакции записи — `ПередЗаписью`, `ПриЗаписи`, `ОбработкаПроведения` у
  документов (2.2).
- Проверять остаток ресурса в транзакции записи только когда так же проверяют все изменяющие ресурс
  документы; иначе — вне транзакции (2.2).
- Каждое исключение обосновывать: документ, меняющий контролируемый ресурс без проверок, допустим,
  когда вводится крайне редко (2.2).
- Правило, нарушаемое при записи любого из двух объектов, проверять встречно: либо в транзакции
  обоих, либо вне транзакции обоих (2.2).

**Не надо**
- Другие схемы условной проверки заполнения: они скрывают из свойства «Проверка заполнения» случаи
  условной проверки и затрудняют анализ логики конфигурации (1.2).
- Проверки, которые должны гарантировать целостное состояние объекта или зависящих от него данных,
  например движений (2.2).
- Злоупотреблять количеством проверок в транзакции записи: состояние других объектов базы по ссылкам
  проверять очень редко — в транзакции имеет смысл проверять лишь ресурсы и правила соответствия,
  которые не изменяются без проверок всеми участниками (2.2).

**Совет**
- При подсистеме «Обмен данными» БСП обработчик вызывается и при проведении документов после загрузки
  из сообщения обмена; чтобы отключить часть проверок, анализировать свойство
  `ДополнительныеСвойства`.`ОтложенноеПроведение` (1.4).

**Пример**
```bsl
НепроверяемыеРеквизиты = Новый Массив();
Если ЮрФизЛицо <> Перечисления.ЮрФизЛицо.ФизЛицо Тогда
  НепроверяемыеРеквизиты.Добавить("ИндивидуальныйПредприниматель");
КонецЕсли;
УдалитьНепроверяемыеРеквизитыИзМассива(ПроверяемыеРеквизиты, НепроверяемыеРеквизиты);
```
