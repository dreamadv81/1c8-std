# Общие требования к конфигурации (#std467)

**Суть.** Конфигурация держится на штатных возможностях платформы и работает во всех средах.
Пункт 1.1 — управляемое и обычное приложение.

**Обязательно**
- Использовать только штатные и документированные возможности платформы `1С:Предприятие` (1.1).
- Конфигурацию рассчитывать на все СУБД, ОС, веб-браузеры и режимы платформы; в веб-клиенте
  ключевые возможности доступны без расширения работы с файлами, взаимодействие асинхронно (1.2).
- Ошибок проверки конфигурации не оставлять, кроме обоснованных случаев: обработчики событий формы
  из кода, модальные окна, синхронные вызовы, признак «Вызов сервера», несущественные
  предупреждения (1.3).
- Поддерживать запуск в режимах обычного приложения (толстый клиент) и внешнего соединения для
  администраторов — совместимость с 8.0 и 8.1; отказ только в обоснованных случаях (1.4).
- Имена, синонимы, комментарии и любой текст — по правилам русского языка, без грамматических
  ошибок (2.1).
- Учитывать ограничения на внешние ресурсы (стандарт 794) (1.5).

**Не надо**
- Отходить от умолчаний платформы при проектировании решений, интерфейса и отчётов: альтернативы —
  только в обоснованных случаях (1.5).
- Неиспользуемые объекты метаданных и код, не нужные ни конфигурации, ни интеграции (2.2).

**Совет**
- Ради этого `Использовать управляемые формы в обычном приложении` — `Истина`, `Использовать
  обычные формы в управляемом режиме` — `Ложь`, признаки модулей — по общей схеме, разработка —
  для обоих режимов (1.4).
- Объекты верхнего уровня сортировать по имени, подчинённые — по проектной логике; исключения —
  общие реквизиты, объекты с префиксом «Удалить», группы команд (2.3).
