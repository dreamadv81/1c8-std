# Правила создания общих модулей (#std469)

**Суть.** Контекст исполнения общего модуля задаётся одним из четырёх наборов признаков, а имя —
постфиксом этого набора.

**Обязательно**
- Выбирать для общего модуля один из четырёх контекстов: серверный, серверный для вызова с
  клиента, клиентский, клиент-серверный (1.2, табл.).
- Серверные процедуры и функции размещать в модулях с признаками `Сервер` (флажок `Вызов сервера`
  снят), `Клиент (обычное приложение)`, `Внешнее соединение`: тогда гарантирован вызов с
  параметрами мутабельных типов (`СправочникОбъект`, `ДокументОбъект`); имя — по общим правилам
  именования метаданных (2.1).
- Имя общего модуля совпадает с названием подсистемы или механизма, процедуры которого он
  реализует (3.1).
- Серверные процедуры и функции, доступные клиентскому коду, размещать в модулях с признаком
  `Сервер` и установленным `Вызов сервера`; имя — с постфиксом `ВызовСервера` (`ServerCall`) (2.2).
- Клиентские модули — признаки `Клиент (управляемое приложение)` и `Клиент (обычное приложение)`,
  постфикс `Клиент` (`Client`); иная комбинация — только когда процедуры нужны лишь в одном
  режиме (2.3).
- Клиент-серверные модули — признаки `Клиент (управляемое приложение)`, `Сервер` (`Вызов сервера`
  сброшен), `Клиент (обычное приложение)`, `Внешнее соединение`, постфикс `КлиентСервер`
  (`ClientServer`) (2.4).
- Глобальные модули — постфикс `Глобальный` (`Global`), постфикс `Клиент` к ним не
  добавляется (3.2.1).
- Модули с признаком `Привилегированный` — постфикс `ПолныеПрава` (`FullAccess`) (3.2.2).
- Модули с повторным использованием возвращаемых значений — постфиксы `ПовтИсп` (`Cached`) и
  `КлиентПовтИсп` (`ClientCached`) (3.2.3).
- Модули библиотек, допускающие изменение реализации, — постфиксы `Переопределяемый`
  (`Overridable`) и `КлиентПереопределяемый` (`ClientOverridable`) (3.2.4).
- Модули национальной специфики локализуемых конфигураций — постфиксы `Локализация`
  (`Localization`) и `КлиентЛокализация` (`ClientLocalization`) (3.2.5).

**Не надо**
- Параметры мутабельных типов в экспортных процедурах модулей для вызова с клиента: с клиента и на
  клиент их не передать (2.2).
- Ветвить код клиент-серверного модуля инструкциями препроцессора: различающуюся функциональность
  реализуют в модулях своего типа, пп. 2.1 и 2.3 (2.4).
- Общие слова в именах модулей — «Процедуры», «Функции», «Обработчики», «Модуль»,
  «Функциональность»: только когда полнее раскрывают назначение (3.1).

**Совет**
- В один общий модуль складывать процедуры и функции одной подсистемы либо сходного
  функционального назначения (1.1).
- Постфикс `Сервер` (`Server`) добавлять, когда иначе имя конфликтует со свойством глобального
  контекста (2.1).
- Клиент-серверные модули заводить для процедур, одинаковых на сервере и на клиенте: так не
  дублируется код (2.4).
- Имена общих модулей строить по общим правилам именования метаданных, различая модули одной
  подсистемы постфиксами из пп. 2.1–2.4 (3.1, 3.2).
