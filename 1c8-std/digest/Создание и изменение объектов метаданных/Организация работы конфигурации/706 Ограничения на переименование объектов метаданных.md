# Ограничения на переименование объектов метаданных (#std706)

**Суть.** Переименование объекта метаданных рвёт связи по имени: при объединении конфигураций, при
обновлении на поддержке и в хранимых ссылках.

**Обязательно**
- Вместо переименования общего модуля создавать новый общий модуль с новым именем и переносить в
  него код исходного (1).
- Устаревший объект, вместо которого заводят новый с тем же именем, переименовывать с префиксом
  `Удалить`: иначе обновление на поддержке не пройдёт из-за двух объектов с одним именем (2).

**Не надо**
- Переименовывать общий модуль и создавать новый с тем же именем: подписки свяжутся по имени с
  новым модулем, где нужных процедур нет (1).
- Хранить в `ИдентификаторыОбъектовМетаданных` ссылки на объекты метаданных других конфигураций:
  для них заводят строковые реквизиты и механизмы актуальности (3.3).
- Переименовывать объект с последующим созданием нового с тем же полным именем и переименовывать
  дважды в текущей и младших версиях при параллельных ветках: делают это только в самой последней
  версии, иначе переименование учтётся дважды; при ссылках на `ИдентификаторыОбъектовМетаданных`
  запрет касается ролей и подсистем (3.4).

**Совет**
- Без `Библиотеки стандартных подсистем` ссылки на объекты метаданных хранить строковыми
  реквизитами (`Строка`, 255) с полными именами и менять или удалять хранимые имена при обновлении
  базы (3, 3.1).
- При `Библиотеке стандартных подсистем` — ссылки на справочник `ИдентификаторыОбъектовМетаданных`:
  он сам отслеживает переименования, удаления и добавления и короче строки 255; переименования
  ролей и подсистем описывают явно (3.2).

См. также: 534 (удаление устаревших объектов метаданных).
