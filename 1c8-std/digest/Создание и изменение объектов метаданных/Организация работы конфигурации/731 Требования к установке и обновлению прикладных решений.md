# Требования к установке и обновлению прикладных решений (#std731)

**Суть.** Раскладка каталога шаблонов, файл-манифест и уникальное название разработчика —
требования к дистрибутиву.

**Обязательно**
- Дистрибутивы установки и обновления готовить по главе 30 «Поставка и поддержка конфигурации»
  Руководства разработчика (1).
- Поставляемые шаблоны класть по пути ниже; в каталоге версии точки заменяются
  подчёркиваниями (2).
- В каталоге версии — файл-манифест `1cv8.mft` с описанием шаблонов конфигурации (`.cf`) и
  демонстрационных информационных баз (`.dt`) (3).
- Названия разработчика-поставщика должны быть глобально уникальными: одно
  для наименований шаблонов конфигураций, другое для имён файловых каталогов (4.2).

**Совет**
- В строке `Catalog` манифеста название разработчика включать в наименование шаблона явно (часть
  до «/»), в строке `Destination` — `<каталог разработчика>\<каталог информационной базы>`: так
  названия конфигураций не совпадут (4.1).
- Обновления выпускать отдельными дистрибутивами с файлом `.cfu`; основной способ — поиск файлов
  обновления (`Конфигурация – Поддержка – Обновить конфигурацию`), при `Библиотеке стандартных
  подсистем` — подсистема «Обновление конфигурации» (5).

**Пример**
```bsl
<Каталог шаблонов>\<каталог разработчика>\<каталог конфигурации>\<каталог версии>
```
