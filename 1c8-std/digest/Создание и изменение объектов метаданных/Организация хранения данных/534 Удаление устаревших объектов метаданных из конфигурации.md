# Удаление устаревших объектов метаданных из конфигурации (#std534)

**Суть.** Устаревший объект метаданных помечают префиксом `Удалить`, переносят данные и убирают,
когда старой версией не пользуются.

**Обязательно**
- Планируя удалить объект метаданных с записями в базе, решить: удалять или переносить (1).
- Помечать устаревшее префиксом `Удалить` (англ. `Obsolete`) в имени (1.1).
- Обеспечить перенос данных устаревшего в новую структуру (1.2).
- Обращения к устаревшему заменить всюду: исключить из ролей (кроме `ПолныеПрава`,
  `АдминистраторСистемы`) и подписок, удалить избыточные код, формы, макеты, команды, кроме кода
  переноса (1.4).
- Устаревшее сортировать в дереве метаданных по общим требованиям (1.5).
- При удалении измерения регистра сведений или сокращении типа (в том числе удалении значения
  перечисления из типа) — новый регистр с переносом записей либо `Режим сокращения типа` в
  `Удалять данные`, когда данные можно удалять: иначе ошибка «Записи регистра стали
  неуникальными» (2).
- `Удалять данные` обязательно при универсальном типе измерения и у измерения библиотечного
  регистра в типовых решениях (2).
- Удалять помеченное `Удалить` безвозвратно только когда переход идёт через версию с переносом
  либо старой версией не пользуются (3).

**Не надо**
- Удалять устаревшее безвозвратно, не пометив (1.1).

**Совет**
- В синоним добавлять префикс «(не используется)» (англ. «(not used)»), в том числе
  стандартному (1.1).
- Движения устаревшего документа-регистратора сохранять: запретить генерацию движений при
  проведении и снятие пометки удаления, сменить регистратор на замещающий, пометить
  документы на удаление (1.3).
- Очистить устаревшие данные; при ошибкоёмком переносе не сразу (1.6).
- Перед безвозвратным удалением бывает нужен релиз с очисткой: иначе реструктуризация даст
  ошибку (3).
- Новый регистр не нужен при добавлении измерения или расширении типов (2).

См. также: 689 (настройка ролей и прав доступа).
