# Использование предопределенных элементов (#std697)

**Суть.** Предопределённые элементы справочников, планов счетов, видов характеристик и расчёта
создают автоматически, программно — лишь при зависимости от условия. Платформа 8.3.3+ без
совместимости с 8.2; уточнение у 1.2: управляемое и обычное приложение.

**Обязательно**
- `ОбновлениеПредопределенныхДанных` — `Авто` (1.2).
- `ИнтерактивноеУдалениеПредопределенныхДанных`,
  `ИнтерактивнаяПометкаУдаленияПредопределенныхДанных`,
  `ИнтерактивноеСнятиеПометкиУдаленияПредопределенныхДанных`,
  `ИнтерактивноеУдалениеПомеченныхПредопределенныхДанных` выключить во всех ролях (1.2).
- В дочерних узлах РИБ элементы не создаются: сообщение обмена загружают раньше обращающегося
  кода (1.3).
- Таблицам вне плана обмена РИБ, на которые не ссылаются его таблицы, —
  `ОбновлятьАвтоматически`: `Авто` у подчинённого узла — `НеОбновлятьАвтоматически` (1.4).
- При совместимости с 8.3.3 включать `УстановитьОбновлениеПредопределенныхДанных` при первом
  запуске узла (1.4).
- Наличие элементов зависит от условия — «Не обновлять автоматически», код создания и пометки
  недействительным, учёт отсутствия (2).

**Не надо**
- Программные вызовы `УстановитьОбновлениеПредопределенныхДанных` для смены режима (1.2).
- Обращаться к элементам в `ПриПолученииДанныхОтГлавного` и правилах регистрации: загружены
  не всегда (1.3).
- Выполнять в подчинённых узлах обработчики обновления с предопределёнными элементами (1.3).

**Совет**
- В большинстве случаев создавать элементы автоматически (1.2).
- С подсистемой «Обмен данными» «Библиотеки стандартных подсистем» 2.1.4+ снимаются первые два
  требования, третье остаётся (1.3).
- С «Библиотекой стандартных подсистем» 2.1.4+ — `ПредопределенныйЭлемент` модулей
  `ОбщегоНазначения` и `ОбщегоНазначенияКлиент`: отсутствующим `Неопределено` (2).

См. также: 488 (стандартные роли), 638 (недействительные объекты), 443 (предопределённые значения на клиенте).
