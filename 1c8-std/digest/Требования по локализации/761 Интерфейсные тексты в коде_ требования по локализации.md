# Интерфейсные тексты в коде: требования по локализации (#std761)

**Суть.** Строки для пользователя в модулях оборачивают `НСтр` и собирают целыми фразами через
`СтрШаблон`; имена объектов метаданных и внутренние идентификаторы пользователю не показывают.

**Обязательно**
- Строки для пользовательского интерфейса (сообщения, надписи в формах, названия и подсказки
  команд, выражения в настройках СКД) делать локализуемыми: применять `НСтр` вместо строковых
  литералов (1).
- `НСтр` применять к самому литералу, а не к переменной, в которую он положен (1).
- Составную строку, части которой зависят от условий, собирать логически завершёнными, целостными
  фразами, подставляя параметры функцией `СтрШаблон` или аналогичной (2).
- Именованные параметры подстановки допустимы только в двух вариантах — `[Параметр]` и
  `%Параметр%`; имя — по правилам образования имён переменных (2).
- В функции `НСтр` строку ограничивать одинарными кавычками (4).
- Выводя имена процедур и функций, давать полные имена с именем общего модуля или модуля
  менеджера (5.1).
- Собирая сообщение сложением строк, неязыковые символы (чаще перенос строки) в начале и конце
  строк выделять в отдельные строковые литералы (8).
- Нет нужной кнопки в перечислении `КодВозвратаДиалога` — задавать вместе со значением его
  представление функцией `НСтр` (9).
- С БСП для составных форматированных строк применять функцию `ФорматированнаяСтрока` общих
  модулей `СтроковыеФункции` или `СтроковыеФункцииКлиент` вместо объекта
  `ФорматированнаяСтрока` (3).

**Не надо**
- Иное использование строк, предназначенных для пользовательского интерфейса, кроме `НСтр` (1).
- Разрывать параметрами подстановки целостную фразу на логически незавершённые части: вместо
  этого задавать в коде несколько строк со всеми вариантами фразы (2).
- Выводить в пользовательском интерфейсе, сообщениях, справочной информации и других материалах
  имена объектов метаданных и внутренние идентификаторы, которые используются в коде (5).
- Указывать параметр «Л=» («L=») в строке форматирования у `ЧислоПрописью`,
  `ПредставлениеПериода`, `СтрокаСЧислом` (6).
- Вызывать `ПолучитьСклоненияСтрокиПоЧислу` — она только для русскоязычного интерфейса; вместо неё
  `СтроковыеФункцииКлиентСервер.СтрокаСЧисломДляЛюбогоЯзыка`,
  `РаботаСКурсамиВалют.СформироватьСуммуПрописью`, `СтрокаСЧислом`, `ЧислоПрописью` или
  собственные прикладные функции (7).

**Совет**
- В пользовательском интерфейсе допустимо выводить синонимы (представления) объектов метаданных и
  представления внутренних идентификаторов (5).
- Синонимы получать напрямую из метаданных функцией `Представление`, а не дублировать в
  текстах (5).
- Исключение — сообщения для разработчиков и интерфейсы инструментов разработчиков или
  внедренцев: там вывод имён объектов метаданных и внутренних идентификаторов предусмотрен (5.1).
- Имена объектов метаданных получать напрямую из метаданных функцией `ПолноеИмя` (5.1).
- В `ПоказатьВопрос` по возможности использовать системное перечисление `КодВозвратаДиалога` (9).
- Допустимо составлять текст из нескольких предложений, каждое в своём `НСтр`, и предложения,
  заканчивающиеся двоеточием (2).
- Сложение строк вместо шаблона допустимо в редких случаях — например, длинное сообщение с логом
  действий (8).

**Пример**
```bsl
ПоказатьПредупреждение(, НСтр("ru='Переменная типа ""Строка""'"));
```
