# Макеты: требования по локализации и поддержке разных языков интерфейса (#std766)

**Суть.** Макет, который копируют, а не переводят, помечают постфиксом кода языка; язык макета
задаётся свойством — форма выходит не на языке интерфейса.

**Обязательно**
- Макет, который при переводе копируют (двоичные печатные формы офисных форматов, HTML-макеты с
  изображениями), помечать постфиксом кода языка из свойства `Код языка`:
  `ПФ_ODT_СчетНаОплату_ru` (1).
- Добавляя языки интерфейса, добавлять макеты с такими постфиксами, а в коде брать макет по
  текущему языку — `ПолучитьОбщийМакет(Имя + "_" + ТекущийЯзык())` (1).
- Данные макета на языке, отличном от интерфейсного, получать через `КодЯзыка` (табличный
  документ) или `КодЯзыкаМакета` (текстовый и HTML-макет) (2).
- Макеты, выводимые строго на одном языке, помечать постфиксом кода языка, при
  программном получении задавать код языка макета, а в текстах для них явно указывать второй
  параметр `НСтр` — код того же языка (3).
- Именованные параметры подстановки в макетах подчинять требованиям к интерфейсным текстам в
  коде (4).
- Кодировка макетов — UTF-8 (5).
- Внешние компоненты размещать в макетах типа «внешняя компонента»; компонента обязана
  обрабатывать `SetLocale`, а при непредусмотренном коде — настраивать окружение на
  английский (7).

**Не надо**
- Переводить на другие языки макеты, выводимые строго на одном языке (3).

**Совет**
- Получать макет в три этапа: по `ТекущийЯзык()`, по коду основного языка, по `ИмяМакета`; затем
  установить `КодЯзыка` или `КодЯзыкаМакета` (1).
- По возможности группировать однотипные макеты, беря один вместо нескольких; имя собирают
  подстановкой кода языка: `Сообщения_%1` (6, рис.).
- С БСП и подсистемой «Печать» макет брать `УправлениеПечатью.МакетПечатнойФормы`: она вернёт
  макет с постфиксом и установит `КодЯзыка` (3).
